save plugin: its settings panel

restore points settings
The restore points panel (web/src/cplugs/save/SaveSettings.svelte, with LocationPanel.svelte, StoragePanel.svelte and ScopePanel.svelte in the panel kit's .tm frame) reaches the plugin's pane as a settings-panel contribution and shows only while the plugin is on, with the same routes and stored values as before it moved into the pane.
vault location
LocationPanel.svelte (#1956): the plugin setting vaultLocation as a .oc-field folder field in a .tm__field label, the folder in force and whether it can be used in .tm__sub, a refused or unusable folder in .tm__problem, the same-disk and left-behind advice in the framed .tm__warn, and a quiet .oc-btn "use default" beside the confirm .oc-btn--confirm "save location" in .tm__actions. It writes through the plugin settings route; it adds no class.
plugin folders
FolderUnits.svelte (#1955), under the storage meter, adds no class: one .tm__srv row per backed-up plugin folder in .tm__servers (.tm__srv-name for the plugin and data id, .tm__sub for size, restore points and the relative last backup, a .oc-btn.oc-btn--sm restore). Restore asks inline in a .tm__warn block with an .oc-field point picker and an .oc-btn cancel and .oc-btn--confirm pair; the result line is .tm__note and names the new folder. With none, one dim .tm__sub line says so.
