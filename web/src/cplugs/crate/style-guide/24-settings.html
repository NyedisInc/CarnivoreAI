crate plugin: its settings panel

crates settings
The crates plugin's block (web/src/cplugs/crate/CratePanel.svelte, a settings-panel contribution) is the same .tm column cut into regions by hairlines (.crt-region, each under a .pl-label): the folders, the running job, and the recorded crates as hairline rows (.crt-row: .crt-row__name bright, .crt-row__meta and one .crt-row__where per copy dim, quiet .oc-btn--sm verify and copy in .crt-row__acts); a folder or copy in trouble says so in .tm__problem. A job's progress is JobProgress.svelte (.crt-job, its .crt-job__head the tracked label, the phase and a quiet cancel): the shared fill LimitGauge with the byte and file counts under it, then the outcome, done in .tm__note, failed or cancelled in .tm__problem; it moves on its pushed job topic, never on a timer while the push is up.
crates: restored list and download
web/src/cplugs/crate/RestoredList.svelte is one more .crt-region under a .pl-label: the finished restores as one-line hairline rows (.crt-row.crt-row--line) with the project name, when and the counts dim, and a quiet .oc-btn--sm "undo" that opens UndoDialog.svelte; an undone restore keeps its row with no button. Every crate row (recorded, found, and the project page's) also has a quiet .oc-btn--sm "download": an <a download> to the streamed download route, so the browser saves the file with no script.
