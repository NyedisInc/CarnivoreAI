crate plugin: its settings panel

crates settings
The crates plugin's block (web/src/cplugs/crate/CratePanel.svelte, a settings-panel contribution) is the same .tm column holding base cards (one per region, titled): the folders, the running job (.crt-region, a hairline above it), and the recorded crates as base list rows (name, then what it covers and when it was written and verified, and one .crt-row__where per copy dim); each row's quiet small buttons (restore, verify, copy, download and a coral remove) sit on their own wrapping line (.crt-acts); a folder or copy in trouble says so in .tm__problem. A job's progress is JobProgress.svelte (.crt-job, its .crt-job__head the tracked label, the phase and a quiet cancel): the shared fill LimitGauge with the byte and file counts under it, then the outcome, done in .tm__note, failed or cancelled in .tm__problem; it moves on its pushed job topic, never on a timer while the push is up.
crates: restored list and download
web/src/cplugs/crate/RestoredList.svelte is one more base card: the finished restores as base list rows with the project name, when and the counts dim, and a coral small "undo" that opens UndoDialog.svelte; an undone restore keeps its row with no button. Every crate row (recorded, found, and the project page's) also has a quiet small "download" button that fetches the streamed download route with the bearer token and saves the file.
