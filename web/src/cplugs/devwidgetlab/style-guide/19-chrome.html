widget lab plugin: the developer page that frames the widget harness

widget lab menu and viewer
The Widget Lab plugin (Joe (ccsliinc), 2026-10-18, issues #1939 and #1944, docs/widget-lab.md) is a developer tool, off by default, in two halves that copy the flow chat view and the review board. THE MENU is the lab tab's slide-out (web/src/cplugs/devwidgetlab/LabMenu.svelte, .dwl-menu, about 276px usable), built to the Widget Lab design draft's structure and hierarchy: where anything is chosen or started. Top to bottom, in ONE scroll region (.dwl-scroll) of folding blocks (MenuSection.svelte, .dwl-sec, a base row Button (data-sec-head) with the shared FoldChevron, .dwl-sec-label, .dwl-sec-value, .dwl-sec-body): a block header always ends in its current value (yellow for an edit not applied yet, coral for failing checks). First the find row (FindRow.svelte, .dwl-filter, .dwl-search holding the base search Field, data-result the base Select for the results), then the widget tree: one top-level "widgets" fold (data-group-root) that shows or hides every group at once, the groups under it (data-group-nested); Shift+click on any chevron folds or unfolds every fold, and the chevron turns into the double chevron while Shift is held (the left menu's cue). Then PREVIEW, open by default (LabControls.svelte, .dwl-rows): "show in", a dropdown whose rows are checks (the shared ChoiceDropdown in its multiple form, rows .dwl-pick over the shared .oc-check; all six places are always listed, one the widget does not declare wears .dwl-pick--off (muted) with its .dwl-pick-note "not used yet", and a new draft can still tick it to add that place), the main widths (hidden for now) as base Checkboxes (data-width-choice) behind a "more sizes" fold (a base Button, data-more-key), "sample data" as a single-select ChoiceDropdown (.dwl-pick-text), and LAST the theme, a base Select with a base IconButton step key each side (.dwl-seg--theme). The folded SCENARIO block; the CAPTURE block (CaptureFooter.svelte, .dwl-foot) holding the ONE confirm-colored key, the base Button at variant="confirm", and its note; the CHECKS block LAST (ChecksSection.svelte, .dwl-checks): a scope select (.dwl-row, .dwl-label, the base Select), the outlined primary base Button "run checks" beside the quiet "results" key (.dwl-run-row), a one-line summary (.dwl-note, data-tone green or coral), the catalog tick (a base Checkbox) and a muted note (.dwl-note--muted); and under the region a quiet link row (.dwl-links, .dwl-link). The viewer's pop-out key is the home screen's own float (.dwl-open-float, copied from HomeOpenMenu.svelte: the faint float key, the base IconButton's float variant, at the top right of the main screen, out of flow). THE VIEWER is the page in the main screen (LabViewer.svelte, .dwl), for looking only: a title strip (.dwl-strip, a fixed minimum height, a hairline under it via box-shadow) holding the widget's name (.dwl-strip-name, the ONE accent-colored label: small tracked capitals in --oc-orange; the page's own title is the tab's, never repeated), its id (.dwl-hint) and the view switch (.dwl-views); one muted context line (.dwl-context, .dwl-hint); then .dwl-viewer, which scrolls on its own: one band per host, a dim line for hosts the widget does not declare (.dwl-undeclared), and the capture log. In a phone-wide page the bands become host tabs (.dwl-hosttabs, a base Segmented) and frames are scaled to fit (.dwl-zoom). Hairlines separate regions; there are no cards.
widget lab host band and frame
HostBand.svelte (.dwl-host) is one place a widget is drawn: a title row (.dwl-host-head, .dwl-host-name) with the status word (.dwl-chip, --oc-green for declared, .dwl-chip--off in --oc-coral), a folded table of the published sizes (.dwl-sizes, .dwl-sizes-table), SIZE SWITCHES beside the host name (.dwl-band-sizes, a base Segmented whose options carry data-size-name, the current size picked; the rest in a small base Select, data-size-more): each band keeps its own size, so a band draws ONE size, and the right and bottom drawers, which have no published sizes, show no switches; and the previews (.dwl-previews, a wrapping row; each .dwl-preview is one size at true size). The caption (.dwl-preview-cap) holds a key (a base Button, data-cap-key) that focuses the frame (the others dim, data-dim; the focused one's stage takes a brighter hairline) and the fit table's verdict (.dwl-verdict: pass, fail or clip). Under the frame only what matters: .dwl-note, .dwl-note--error in --oc-coral, .dwl-findings. LabFrame.svelte draws the harness page in an iframe (.dwl-frame in .dwl-frame-wrap) in a box that hugs the widget's own published size (its width and height set inline, the harness's stage padding cropped; the whole window only while the widget's menu is open), never sized from the page; .dwl-stage holds it with its own 1px hairline and scrolls the frame inside it when the page is narrower. Focus is the shared rule.
widget lab tree
WidgetTree.svelte (.dwl-tree) is the lab's COLLAPSIBLE tree, grouped as the widget drawer files widgets (their manifest category). First the "all widgets" card (a base row Button, data-all-fit, .dwl-all-text, .dwl-all-name, .dwl-all-sub: an icon, the name over "full-page review", the count), which shows the fit table in the viewer and wears the accent edge while it is on show (picking a widget shows the widget; there is no switch). Then one quiet uppercase fold row per category (a base row Button, data-tree-group, with the shared FoldChevron and its count .dwl-group-count, then the group's failing count .dwl-group-fail in --oc-coral); the group holding the picked widget starts open, the folds the person sets are kept in the lab's own devwidgetlab.tree.folds key, and a filter opens every group that still has a row. The drafts ("new items") are a LAST group appended through the menu's trailing prop, drawn folded with a count of 0 while empty. Rows (a base row Button, data-tree-leaf, nested data-leaf-nested, the name in .dwl-leaf-name) are hairline-ruled by box-shadow; the picked one (aria-current) reads brighter on the title-row ground. A row starts with a status dot (.dwl-dot) and ends in the gate's status word (.dwl-verdict, data-verdict: "not checked" muted, pass in --oc-green, "fails N" in --oc-coral, always a word as well as a color). An empty tree says why (.dwl-tree-empty). Inside "new items" the draft rows are filed under their category: a quiet label row (.dwl-draft-cat, the drawer's category name in small tracked capitals) before the first draft of each category, other last. A right-click on a row opens WidgetTreeMenu.svelte: the app's one cascade menu (as the sidebar rail's right-click menu), read-only (show in viewer, copy key), hung from the zero-size marker .dwl-tree-menu-anchor at the pointer, inside .dwl-pointer-menu, which undoes a scaled frame's CSS zoom so the menu's top-left corner is the pointer (4px under it, as the app's).
widget lab host chrome and free resize
HostChrome.svelte (.dwl-chrome) draws each frame inside a mock of the surface it is hosted on, inert (but for the lit widget-bar key, whose right-click opens the frame's real bar key menu through key-menu-bridge.ts) and square-cornered, wearing the real classes: the drawer is one of the app's THREE REAL drawers, chosen by the PREVIEW block's drawer picker (DrawerChrome.svelte, .dwl-dock): the LEFT drawer, which is the app's own left sidebar imported at run time from client/index.html and drawn by the same mount functions (widget-harness/sidebar/, no copy), so it looks as it does in the app at every width, folded, with the widget area closed, glance or full, and at each row density; its band header offers those states (SidebarControls.svelte, .dwl-sidebar-controls, .dwl-sidebar-group), or the slide-out of the RIGHT or BOTTOM widget bar (.dwl-dock-panel, --side or --bottom, the panel ground, the real RailResizeHandle as its inner edge in .dwl-dock-grip, beside or above its bar DockBar.svelte with the widget's own key lit, aria-pressed in the accent edge); the terminal grid (.dwl-chrome--terminal) sits above the bottom widget bar (.dwl-chrome-bar, DockBar.svelte, over the real .rail__layer, with .dwl-chrome-key keys); the home grid (.dwl-chrome--home) is a grid cell on the page ground; the pop-out window (.dwl-chrome--popout) has a bar (.dwl-chrome-window, .dwl-chrome-window-title). The widget head and buttons inside the frame are the real cell's. ResizeBox.svelte (.dwl-resize) puts a handle on the right edge, bottom edge and corner (.dwl-handle--e, --s, --se, separators, arrow keys step 8px or 32px with Shift, Home resets); the caption shows the live W x H and the nearest published size (.dwl-dims) and a reset key (a base Button, data-reset). The harness redraws and fit-checks the widget at the dragged box; the fit table's verdict then reads "for <size>". A RIGHT or BOTTOM drawer fills its panel body square, edge to edge (the real RailCellBody, no box of its own), at the real default (378 x 800 right, 1244 x 318 bottom), and has ONE handle on the panel's inner edge (.dwl-handle--w over the real RailResizeHandle line for the right drawer, drag left to widen; .dwl-handle--n for the bottom drawer, drag up to grow); the caption names the drawer and the reset key returns to the default panel. The COMPARE view's pair (ComparePair.svelte, .dwl-pair) draws both sides in the same host chrome and with the same resize handles; the box is the pair's, so resizing one side resizes the other, and one caption (.dwl-dims, data-reset) reads it. MainViewHost.svelte is the root a tab's main-area view (mainView) is laid over the main content area in while its slide-out is open. The mock bars around the frame (the pop-out window bar and the widget bars) always draw; the frame's menus open from the preview and are drawn by the lab page in its top layer.
widget lab JSON box and capture log
ScenarioBox.svelte (.dwl-scenario, in the SCENARIO section) is a mono base multiline Field (data-scenario-text) whose text is only parsed, with one sentence under it: .dwl-note--ok in --oc-green when it checks out, .dwl-note--error in --oc-coral when it does not; apply is the calm .oc-btn--confirm. CaptureResults.svelte (a fold at the bottom of the viewer, .dwl-results, .dwl-result-list, .dwl-result, .dwl-result-head, .dwl-path) lists each capture newest first with a captured or failed word, every failure reason, and the PNG and metadata paths as selectable mono text. A failed capture is never drawn as a pass. Tokens only; 320 px up.
widget lab fit table
The viewer's fit table (FitTable.svelte, .dwl-fit), shown when the tree's top entry is picked. It only shows: the run is started from the menu's MATRIX section. One count line and .dwl-fit-scroll holding the grid (.dwl-fit-table): a sticky first column of widget ids (a quiet base Button, data-fit-name, picks the widget; .dwl-fit-widget) and one column per host and size, hairlines between rows by box-shadow. Each cell is a quiet base Button (data-fit-cell) whose data-state is pass in --oc-green, fail in --oc-coral, red (clipping or overflow: coral with a 1px coral outline, so it reads without color) or unsupported (a quiet dash where the widget does not declare that host or size). Pressing a cell picks widget, host and size, and the viewer returns to the widget view with that frame focused. Tokens only; the grid scrolls inside its own container at 320 px.
widget lab drafts
A draft is a widget being made or revised in the lab's own storage (Joe (ccsliinc), 2026-10-18, docs/widget-lab.md section 9), built from a source folder the lab finds itself (or the one set in Settings). DraftActions.svelte (.dwl-actions, two quiet keys, "+ new" and "make a revision"; one sentence .dwl-actions-note when no source folder is found, pointing to Settings) sits under the tree; DraftForm.svelte (.dwl-form, base Fields, a Select and Checkboxes) stands in place of the tree while a draft is being asked for. The tree's last group is DRAFTS (data-leaf-draft, a kind tag .dwl-draft-tag and a state word .dwl-draft-state on each row). A picked draft opens the REVISION section (DraftPanel.svelte, .dwl-draft, .dwl-context-list): rebuild, hand to claude, side by side or draft only, discard behind its own confirm; there is NO land key, the work ships through its Task Manager item and Joe's tick. The compare view (DraftCompare.svelte, .dwl-compare, .dwl-compare-strip with the byte delta) lays the current widget beside the draft's built page (ComparePair.svelte, .dwl-pair, .dwl-pair-sides, .dwl-pair-side, captions .dwl-side-cap and .dwl-cap-text) at the same size, theme and fixture; a new widget is drawn alone.
idle traffic readout
Each preview's caption carries one small key, "idle traffic" (IdleReadout.svelte, the shared .oc-btn--sm). Pressed, it measures the widget in a hidden frame opened with idle=1 (a virtual clock over the page's timers: a simulated minute shown and one hidden, the app shell's own reads left out) and leaves one word beside the key in the verdict look (.dwl-verdict): green "idle 0 hidden / 0 shown" when a hidden widget sends nothing, coral with the count otherwise, the routes behind it in its title. The same check runs from the command line over every widget (python3 -m scripts.widgets.idle).
