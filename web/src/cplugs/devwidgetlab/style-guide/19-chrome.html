widget lab host band and frame
HostBand.svelte (.dwl-host) is one place a widget is drawn: a title row (.dwl-host-head, .dwl-host-name) with the status word (.dwl-chip, --oc-green for declared, .dwl-chip--off in --oc-coral), a folded table of the published sizes (.dwl-sizes, .dwl-sizes-table), SIZE SWITCHES beside the host name (.dwl-band-sizes, the quiet outlined .oc-btn--sm keys .dwl-size-key, the current size lit by data-on in the accent edge; the rest behind a small .dwl-size-more menu whose list is .dwl-size-more-list): each band keeps its own size, so a band draws ONE size, and the right and bottom drawers, which have no published sizes, show no switches; and the previews (.dwl-previews, a wrapping row; each .dwl-preview is one size at true size). The caption (.dwl-preview-cap) holds a key (.dwl-cap-key) that focuses the frame (the others dim, data-dim; the focused one's stage takes a brighter hairline) and the fit table's verdict (.dwl-verdict: pass, fail or clip). Under the frame only what matters: .dwl-note, .dwl-note--error in --oc-coral, .dwl-findings. LabFrame.svelte draws the harness page in an iframe (.dwl-frame in .dwl-frame-wrap) in a box that hugs the widget's own published size (its width and height set inline, the harness's stage padding cropped; the whole window only while the widget's menu is open), never sized from the page; .dwl-stage holds it with its own 1px hairline and scrolls the frame inside it when the page is narrower. Focus is the shared rule.

widget lab host chrome and free resize
HostChrome.svelte (.dwl-chrome) draws each frame inside a mock of the surface it is hosted on, inert (but for the lit widget-bar key, whose right-click opens the frame's real bar key menu through key-menu-bridge.ts) and square-cornered, wearing the real classes: the drawer is one of the app's THREE REAL drawers, chosen by the PREVIEW block's drawer picker (DrawerChrome.svelte, .dwl-dock): the LEFT drawer, which is the app's own left sidebar imported at run time from client/index.html and drawn by the same mount functions (widget-harness/sidebar/, no copy), so it looks as it does in the app at every width, folded, with the widget area closed, glance or full, and at each row density; its band header offers those states (SidebarControls.svelte, .dwl-sidebar-controls, .dwl-sidebar-group), or the slide-out of the RIGHT or BOTTOM widget bar (.dwl-dock-panel, --side or --bottom, the panel ground, the real RailResizeHandle as its inner edge in .dwl-dock-grip, beside or above its bar DockBar.svelte with the widget's own key lit, aria-pressed in the accent edge); the terminal grid (.dwl-chrome--terminal) sits above the bottom widget bar (.dwl-chrome-bar, DockBar.svelte, over the real .rail__layer, with .dwl-chrome-key keys); the home grid (.dwl-chrome--home) is a grid cell on the page ground; the pop-out window (.dwl-chrome--popout) has a bar (.dwl-chrome-window, .dwl-chrome-window-title). The widget head and buttons inside the frame are the real cell's. ResizeBox.svelte (.dwl-resize) puts a handle on the right edge, bottom edge and corner (.dwl-handle--e, --s, --se, separators, arrow keys step 8px or 32px with Shift, Home resets); the caption shows the live W x H and the nearest published size (.dwl-dims) and a reset key (.dwl-reset). The harness redraws and fit-checks the widget at the dragged box; the fit table's verdict then reads "for <size>". A RIGHT or BOTTOM drawer fills its panel body square, edge to edge (the real RailCellBody, no box of its own), at the real default (378 x 800 right, 1244 x 318 bottom), and has ONE handle on the panel's inner edge (.dwl-handle--w over the real RailResizeHandle line for the right drawer, drag left to widen; .dwl-handle--n for the bottom drawer, drag up to grow); the caption names the drawer and the reset key returns to the default panel. The COMPARE view's pair (ComparePair.svelte, .dwl-pair) draws both sides in the same host chrome and with the same resize handles; the box is the pair's, so resizing one side resizes the other, and one caption (.dwl-dims, .dwl-reset) reads it. MainViewHost.svelte is the root a tab's main-area view (mainView) is laid over the main content area in while its slide-out is open. The mock bars around the frame (the pop-out window bar and the widget bars) always draw; the frame's menus open from the preview and are drawn by the lab page in its top layer.
widget lab JSON box and capture log
ScenarioBox.svelte (.dwl-scenario, in the SCENARIO section) is a mono textarea (.dwl-scenario-text, the shared .oc-field) whose text is only parsed, with one sentence under it: .dwl-note--ok in --oc-green when it checks out, .dwl-note--error in --oc-coral when it does not; apply is the calm .oc-btn--confirm. CaptureResults.svelte (a fold at the bottom of the viewer, .dwl-results, .dwl-result-list, .dwl-result, .dwl-result-head, .dwl-path) lists each capture newest first with a captured or failed word, every failure reason, and the PNG and metadata paths as selectable mono text. A failed capture is never drawn as a pass. Tokens only; 320 px up.
widget lab fit table
The viewer's fit table (FitTable.svelte, .dwl-fit), shown when the tree's top entry is picked. It only shows: the run is started from the menu's MATRIX section. One count line and .dwl-fit-scroll holding the grid (.dwl-fit-table): a sticky first column of widget ids (a flat key, .dwl-fit-name, picks the widget; .dwl-fit-widget) and one column per host and size, hairlines between rows by box-shadow. Each cell is a flat mono button (.dwl-fit-cell) whose data-state is pass in --oc-green, fail in --oc-coral, red (clipping or overflow: coral with a 1px coral outline, so it reads without color) or unsupported (a quiet dash where the widget does not declare that host or size). Pressing a cell picks widget, host and size, and the viewer returns to the widget view with that frame focused. Tokens only; the grid scrolls inside its own container at 320 px.
widget lab drafts
idle traffic readout
Each preview's caption carries one small key, "idle traffic" (IdleReadout.svelte, the shared .oc-btn--sm). Pressed, it measures the widget in a hidden frame opened with idle=1 (a virtual clock over the page's timers: a simulated minute shown and one hidden, the app shell's own reads left out) and leaves one word beside the key in the verdict look (.dwl-verdict): green "idle 0 hidden / 0 shown" when a hidden widget sends nothing, coral with the count otherwise, the routes behind it in its title. The same check runs from the command line over every widget (python3 -m scripts.widgets.idle).
