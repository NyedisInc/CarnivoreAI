save plugin: its settings panel

restore points settings
The restore points panel (web/src/plugins/save/SaveSettings.svelte, with LocationPanel.svelte, StoragePanel.svelte and ScopePanel.svelte in the panel kit's .tm frame) reaches the plugin's pane as a settings-panel contribution and shows only while the plugin is on, with the same routes and stored values as before it moved into the pane.
vault location
LocationPanel.svelte (#1956): the plugin setting vaultLocation as a .oc-field folder field in a .tm__field label, the folder in force and whether it can be used in .tm__sub, a refused or unusable folder in .tm__problem, the same-disk and left-behind advice in the framed .tm__warn, and a quiet .oc-btn "use default" beside the confirm .oc-btn--confirm "save location" in .tm__actions. It writes through the plugin settings route; it adds no class.
plugin folders
FolderUnits.svelte (#1955), under the storage meter, adds no class: one .tm__srv row per backed-up plugin folder in .tm__servers (.tm__srv-name for the plugin and data id, .tm__sub for size, restore points and the relative last backup, a .oc-btn.oc-btn--sm restore). Restore asks inline in a .tm__warn block with an .oc-field point picker and an .oc-btn cancel and .oc-btn--confirm pair; the result line is .tm__note and names the new folder. With none, one dim .tm__sub line says so.
offloaded sessions
OffloadedList.svelte (#2803), under the plugin folders, adds no class. A .oc-key label, then the offload switch (a Check role="switch" in a .tm__srv-head, OFF by default: Joe (ccsliinc), 2026-11-05) with a .tm__sub line that says what its state means. Then one .tm__srv row per offloaded session in .tm__servers, newest first: .tm__srv-name for the session, .tm__sub for project, conversation count, size and day, the state word, and a .oc-btn.oc-btn--sm restore that is ALWAYS drawn (no hover reveal, no row menu). A conflict or failed row adds a .tm__problem line with the reason. Conversations no session holds follow under a second .oc-key heading, "no session". While a staged bulk offload runs (or after the newest ended) one more .tm__srv-head sits under the switch line (slice 6): a .tm__srv-name label, a .tm__sub progress line (offloaded of planned, skipped, failed) and, only while it runs, a .oc-btn.oc-btn--sm stop, always drawn. Fifty rows to a page, then a small "show more" button; the result of a restore is a .tm__note, a refusal a .tm__problem. The list is pushed on the topic cplug.save.offload and polls only while that topic is not live.
