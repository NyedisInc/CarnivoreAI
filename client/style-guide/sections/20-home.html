the home screen lists

Home is the operations center dashboard: a grid of cells (cells) whose lists are running sessions, closed sessions, projects, skills, plugins, themes, the ledger and the activity log. Older launchpad list components still mount through web/src/main.ts for the legacy containers that remain. Both follow the same row rules.

Token, estimated cost, activity, model, project, agent-kind and quota cards appear at the top of new Home layouts; the additive upgrade preserves existing placement and prior hide or remove choices. Token and cost cards show their measured breakdown and price coverage, activity shows observed starts, completions and duration, and model, project and agent-kind rankings show named bars directly. Quota shows one available window at a time with account labels and a sampled history. Cards use short rows of one or two. Each shows its selected period and a server-calculated value above its compact trend or ranking. The Details dialog contains Controls.svelte and its .analytics-options for shared time, filters, collection and coverage. A pinned chart range stays independent of those controls; collection off leaves retained history readable.

running sessions
The cell opscenter/cells/running-sessions/Cell.svelte is a DataTable with a sort control: light, name, project, status word, age.
recent and closed
opscenter/cells/closed-sessions/Cell.svelte: what ended, when, and a restart. Recently deleted rows are the undo list in client/css/recent-deleted.css. A row being opened says so: .oc-open-status in the cell (cyan opening, green opened, coral with the refusal), read from recent-open-status.svelte.ts, with a toast for each step.
projects
opscenter/cells/projects/Cell.svelte: a chevron, the project name, a count, then the project's sessions indented under a gutter. A project's directory is permanent; archived projects hide behind a toggle (.launchpad-archived-toggle).
new
The new item button (.new-fab) opens new session, new project and clone. Starting a project walks name, folder and harness dialogs (ProjectNameModal, ProjectFolderModal, ChoiceModal, CloneModal), every step backed by an API route (docs/DECISIONS.md, API-first).
attach
A session this app did not create is offered through the adopt disclosure (.adopt-disclosure) and the attribution prompt (dialogs). An adopted id is adopted:<tmux-name>; code that parses an id handles both shapes.
empty
.launchpad-empty: one sentence and the action that fills the list. An error card (.launchpad-error-card) says what failed and dismisses.
catalog keys
opscenter.session.*, opscenter.closed.*, opscenter.projects.*, project.name.*, project.folder.*, project.clone.*, and the per-screen assembly in client/js/labels/running-session.js, recent-session.js, project-tree.js.

common mistakes

  • Wrapper against info.session. info.id and info.session.unread are both undefined, silently; activity_status, unread and the family live on the wrapper, id and working_dir on info.session (gotcha 1, the most repeated bug here).
  • A deep link resolved against projects only. Resolve projects first, then live and adopted sessions (gotcha 3).
  • A default for an overwrite-only field. Never ||-default the seven overwrite-only session fields in the data layer (docs/web-build-history.md).
  • Grouping read from the wrong level. Asleep rows landing under "unnamed project" came from a project label read off the wrong level.
