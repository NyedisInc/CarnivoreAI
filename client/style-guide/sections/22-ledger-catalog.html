The four compiled overlay screens, and the canonical references for a new page. Each is a fixed overlay under the header with one scrolling box, a header row, a capped and centred column (1680px), cards in an auto-fill grid, and a single phone breakpoint at 1023px.

colour picker
ColorSwatches (.ledger-tpick) is the account colour picker, used by the add form and the edit form. Closed it is one base button (data-ledger="color-chip": a square of the colour and its hex); it opens a .popup-focus panel (.ledger-tpick__panel, a centred modal on a phone) holding the grid, a preview, the hex field and none. The grid is the xterm 256 palette as ONE sorted grid (xterm-palette.ts, 16 x 16, all 256 indexes once, greys in the first two columns): the greys first, then columns by hue around the wheel, light at the top, as square cells (.ledger-tcell) with hairline gaps in mono type. Hover or focus prints idx 044 #00d7d7 in the readout line; the chosen cell (.ledger-tcell--on) wears a brighter own border, and keyboard focus uses the shared focus rule. Arrow keys move (one cell is in the tab order), enter selects, escape puts back the colour the picker opened with. A hex field (the base bare Field, data-ledger="color-hex") reaches any #rrggbb and a none button (a small base button, data-ledger="color-none") keeps null reachable. A colour within 25 degrees of a status light hue shows a quiet note (.ledger-tpick__note) and is still stored. The palette hexes are data; every chrome colour is a token.

use
Issue #888. The frame PLACES the share actions and the page's adapter BACKS them, each one documented route: exportItem(id) (a GET) draws "export" in the detail pane and hands the document to the one download, web/src/lib/manager-frame/download.ts; remove(id) (a DELETE) draws "remove" beside it. remove
Asks first, in place: the button becomes a question naming the item (.oc-notice--error), a .oc-btn--danger confirm and a quiet "keep it". do not
Execute anything on import, or write before the user has seen what is being installed. A kind with no safe install path (themes arrive only through the signed catalog) offers export only and says so.

the four kinds

common mistakes

  • A table for items the user decides about one at a time. Cards (#535).
  • A status by colour alone. The chip says the state; its colour repeats it.
  • A reset time printed as 12:59. Round to the nearest minute (resetParts).
  • A meter split across two lines. Bar, percent and reset time stay on one line per window.
  • A management page with its own list, search or switch. Mount the manager frame and write an adapter; a second implementation is the junk drawer the frame exists to prevent (#763).
  • A setting the form shows as its default filled in and saved. Absent is not a default: an untouched field is not stored, and "use default" clears a choice rather than writing the default (#888).
  • Hiding what cannot be installed. A catalog that hides things is indistinguishable from one that lacks them; list untrusted items with the reason.
