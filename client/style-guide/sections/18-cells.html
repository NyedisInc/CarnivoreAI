operations center cells, frames and the grid

The home page and the terminal page are grids of cells (the operations center, web/src/opscenter/). Every cell lives in the same frame: CellFrame draws the hairline box and the one widget header (WidgetHead, below: the widget header); the cell draws only its body. A new component on either page is a new cell kind, not a new frame.

frame
<CellFrame meta={metaFor(slot, META)} instance={slot} widthState heightState store body />. Optional: count and suffix after the title, collapsed and onToggleCollapse, summary and total for the phone's one-line summary (PhoneSummary), expanded, onRightControl. The body is a snippet; the frame renders the widget header (WidgetHead.svelte, .oc-frame-title, 31px for every widget) and the menu button (CornerMenu.svelte). The frame on the page terminal has no border of its own.
cell record
Every cell kind is a record in web/src/opscenter/engine/meta.ts: id, titleKey (a catalog key, opscenter.cell.<id>.title), icon and iconTone (a token name without the dashes), showCount, chrome, titleHeight, phoneOrder, the default row, index, fraction and height, minPx and minHeight, and named widthStates and heightStates. The body switches what it shows on the named state, never on a raw pixel width. Every threshold is derived, and says so in a comment.
kinds
The list of record is the folder web/src/opscenter/cells/ and its registry.ts; the kinds today are: activity log, analytics, automations (and all automations), bookmarks (and all bookmarks), browser, changes, closed sessions, crosstalk, developer, files, keep awake, ledger, machine stats, notes, pipeline, plugins, projects, questions, running sessions, scheduled tasks, session contents, skills, stat tile, task list, Task Manager (and all Task Manager lists), tasks (and all tasks), themes, timeline, war room, and the terminal family (terminal, live terminal, viewer, tab group). Each is web/src/opscenter/cells/<kind>/Cell.svelte, mounted by CellHost.svelte.
stat tile
One metric per widget (issue #1157 part 2): working now, sessions (24h), open projects, ledger usage, sessions alive, subagents running, each its own singleton (engine/stat-tile-meta.ts), all drawn by cells/stat-tile/Cell.svelte, which draws nothing itself: it hands the figures to the base component StatTile.svelte (.oc-stat-tile, see "base components"), the one tile the gallery KPI card draws too. The tile is a bare cell (no frame chrome), so .oc-stat-tile--framed draws the card edge: one hairline on --oc-ground-panel, the card's own corner. .oc-stat-tile__head holds the small bare glyph .oc-stat-tile__icon (the tile's own stat tone, --_stat-tone, set from the card's --oc-stat-* token) and the tracked uppercase .oc-stat-tile__label; .oc-stat-tile__body holds the bright .oc-stat-tile__figure (.oc-stat-tile__figure--dim while loading, .oc-stat-tile__figure--note for an endpoint's own sentence) and, two units wide, .oc-stat-tile__delta. The figure is sized from the tile's height. .oc-stat-tile__foot pins to the bottom edge and holds one real secondary line, .oc-stat-tile__sub (of N alive, live and closed, projects with live sessions, reset countdown, stopped, subagent parents), plus a .oc-stat-tile__meter / .oc-stat-tile__meter-fill bar on ledger usage and sessions alive. A shrunk tile (.oc-stat-tile--line) collapses to label left, figure right. Two units tall (.oc-stat-tile--graph) adds .oc-stat-tile__spark, the sampled series. One unit wide is .oc-stat-tile--compact (its side inset is --oc-widget-inset, the same as every tile). Sizes 1 x 1 to 4 x 2 (src/data/widgets.json). A stored layout naming the retired strip (core.stats) gets the six tiles in its place on read (engine/replaced-cells.ts). A tile that reads a note rather than a figure wears .oc-stat-tile--note.

geometry
ONE height, 31px (HEAD_ROW_PX), for every widget on a desktop; below 1024 the whole row is the accordion button that folds the widget and stays 44px (PHONE_HEAD_PX). Padding 0 12px (--oc-space-3), 8px between parts (--oc-space-2, 4px under a 300px cell). Ground --oc-ground-titlerow, a hairline underneath as an inset --oc-line-rule shadow, never a border. The row is the grip the widget is dragged by. THE NARROW-ROW RULES ARE @container oc-head QUERIES (the short title at 400px, the sort at 440px, the arrow at 340px, the count at 240px, the tighter gap at 300px), so every host declares that container on the box the head spans: the grid frame, a drawer card, a rail section, the pop-out window. The phone look (.oc-frame-title--phone, .oc-frame-corner--tap: 44px tap targets, the tighter inset) follows the host's phone state, never the viewport, so a pop-out window or a desktop window under 1024 keeps the 31px row and the controls in it keep their own size (opscenter/controls.css).
the label
The widget's name from the catalog (titleKey; an instance's own title when its cell sets one, a short form at 400px and under when the record has titleShortKey), .oc-frame-name: --oc-fs-title, weight 400, caps, ONE tracking value (--oc-tracking-title), in --oc-orange, the one accent-colored thing in the row, cut by an ellipsis. The count and the suffix after it are --oc-text-secondary.
order, left to right
The icon menu (CornerMenu.svelte, the widget's icon in --oc-text-secondary, never the accent, the gear in --oc-cyan in edit layout, opens CellMenu; a surface with no menu, the pop-out window, draws it inert, .oc-frame-corner--still), the name, count and suffix, a spacer, the option groups (frameHeader.action, then each of frameHeader.groups, then the host's own group), the right control (view all, clear, refresh or the fold chevron), then the close x. Single-row controls that used to sit in a second bar inside a body move up into a group (useHeaderGroup in shell/frame-header.svelte.ts: the timeline's picker and kind key, quiet because the name is the one accent; the crosstalk widget's scope choice and close-thread action are items of its widget menu, not header controls; a pressed or open bare toggle in the row is bright text, never the accent); while no header takes them (ticked off, a phone, a popup with no frame: FrameHeader.takesBars false), and below the width the row needs to hold them (the timeline's key from 260px and picker from 420px), the cell draws them in its body as before. Groups keep the order their cell declares them in. A cell's action goes up only while the header is drawn (FrameHeader.drawn), so a copy with its header off draws it in its body. The terminal viewer's head row (.oc-tv-head--up) is the header's row on a desktop, as the terminal's own head is. A tab strip keeps its own row (frameHeader.strip). On the grid the row is the grip (.oc-frame-title--grip); a drawer card, a rail section and the pop-out are not dragged by it.
separators
THE HEADER DRAWS THEM, NEVER A WIDGET (headParts): one .oc-head-sep, a 1px by 14px --oc-line-rule hairline, between two adjacent non-empty groups and one before the close x. Never leading, trailing or doubled: an empty group draws nothing and takes no separator, and the close x alone takes none. Each group is drawn in a .oc-head-group (display: contents); a group whose only control is the sort, which a cell under 440px drops, is dropped WITH one separator beside it, so a narrow row never starts with a hairline.
the close x
.oc-ibtn.oc-ibtn--bare.oc-ibtn--close (opscenter/controls.css, after the bare hover in the same layer), 20px, a 13px close glyph, dim, the destructive --oc-coral only under the pointer. INSTANT, NO CONFIRM: a singleton is hidden and comes back from the components list, an instance is removed, through the one path the menu's close takes (engine/close-widget.ts; in edit layout the change is final at once). Absent on the terminal page's own pane, on a record with closable: false, and on a phone.
the override flags
On the widget's record (CellMeta), never an id list, so any widget, a plugin's included, opts in: ownHead: true means the cell draws its own head through frameHeader.content or strip and the head is always on (no tick); closable: false keeps the x out. Today only the terminal and the tabbed terminal set both (TERMINAL_META; a browser and a chart set them back).

the body
.oc-wshell: a column that fills the box and clips, the cell's own content inside it. No card, no border, no title: the host's header names the widget. A list or table widget wraps its rows in ShellScroll.svelte (.oc-wshell-scroll), the region that fills the column and scrolls on y, never on x, and is exactly as tall as its rows where the host is auto height (a phone panel).
the controls
Handed up into the host's header while it is drawn (section 11 rule 2). With no header drawn they sit in .oc-wshell-bar, a row at the top of the body padded --oc-space-1; in a bar slide-out with no title row, .oc-wshell-corner takes no room and the control places itself in the body's top right corner. the states
The base state (.oc-state--inline, see base components): ONE plain sentence in place of the body for none, loading, empty and error, the cell's own words or the catalog's (widget.state.*). Error draws the coral bar. Never an empty box and never a spinner.

analytics charts

Each analytics:<uuid> Home cell uses the same quiet summary layout, drawn in the base ChartFrame.svelte (.oc-chart-frame: no title of its own, every row on the header's side inset, --oc-widget-inset): .oc-chart-frame__head carries a meaningful title and period, .analytics-headline presents the server-calculated period value, and .analytics-plot shows the trend with compact axes and gaps preserved. .analytics-caveat reserves a line for partial data so neighboring plots stay aligned. A before-and-after card puts .analytics-change on that same line instead: the change against the equal period before, yellow when .analytics-change--up, cyan when .analytics-change--down, the same words and colours as the kpi tile's delta. The summary has no annotations, legend, slider or toolbars. While the widget header takes bars (a desktop header that is on), the card's range label (.analytics-range, with any .analytics-asof tag) and its details opener are two header option groups, the label first and the opener after it with the header's own hairline between, and the body draws neither .oc-chart-frame__head nor a floating opener; with the header ticked off, or below 1024, they stay in the body as described here. A breakdown card (tokens by project, model, agent kind) draws no total and its rows start under the header, and the plain estimated cost card is a number with no chart under it. .analytics-open is the card's details opener, the faint floating .oc-ibtn--float glyph at the card's top right, taking no room from the title. It opens DetailsModal.svelte (dialogs), the one details dialog: the card's window, the full chart, the figures, rule changes and notes, contributing conversations and the account filters. Theme tokens paint every layer. .analytics-asof is a small quiet tag after the period, as of 14:05, drawn only while the numbers shown are not the latest: the server served a stale answer while it recomputes, a failed read kept the last good one, or a saved snapshot is painting before the live answer lands. It is muted text in the period's own type, never a pill or an alert, and it goes away when a current answer arrives. A chart's configuration is never drawn in its body: it is declared to the widget's settings overlay (the menu's config item).

Analytics cells add supporting regions: .analytics-context and .analytics-metadata carry the scope and source of the figure, .analytics-facts lists its key values (the tokens card wears .analytics-facts--corner inside .analytics-headline--tokens: the four facts as a 2x2 of small labels and right-aligned figures in the headline's top right, wrapping under the total when narrow; .analytics-plot--yield lets the plot give up its height floor first), and .analytics-quota-legend is the quota card's legend: one .analytics-swatch per account in its plotted colour, the account name (ellipsed, never pushing the card wider) and its latest reading, wrapping to one account per line in a narrow card; the chart under it then draws no legend row of its own. A chart card's frame title names the chart (the quota card adds its window, "5-hour window", never the raw id), so the body shows only the period. .analytics-ranking stacks .analytics-ranking-row entries, each with an .analytics-ranking-track and .analytics-ranking-fill bar sized to its share. The list sits in .analytics-ranking-room, the card's leftover height, and draws as many rows as that room holds (down to one line); a short room adds .analytics-ranking--bare, which drops the bars, and the phone, which sizes a card to its content, adds .analytics-ranking-room--free so every row shows. A ranking card and the plain estimated cost card therefore shrink to a list instead of the resize plate; the cost card adds its change against the window before and its hourly average in an .analytics-change line (the cost card's wears .analytics-change--cost, a little air under the unpriced note), then its top models. .analytics-canvas-box--compact holds the chart canvas of a small cell above a floor of 70px, with .chart-legend (a row of swatch and name items, paged by whole items with a pager, never half an item; .chart-legend__item, .chart-legend__pager) above it; .chart-legend__track--wrap is the same row that wraps onto as many lines as it needs and never pages (tokens per agent). Every chart's axis label count follows its plot size (viz/axis.ts: one value tick per 28px of height, one time label per 80px of width, never rotated), and an empty bucket of a summed metric draws as zero; only time the store did not watch (before its first minute, or collection off) is left out, under a faint hatched band. Theme tokens paint every layer.

The default cards add concise facts under the period value: token components and cached share, priced and unpriced cost coverage, observed activity, and visible ranked values. A ranking has no empty chart area. These facts use the server's period summaries and keep missing data distinct from zero.

the grid and drag and drop

surface
GridSurface.svelte lays rows (GridRow, .oc-row) of slots (.oc-cellslot) with --oc-gutter between them. Gutter.svelte and Intersection.svelte are the resize handles between cells and at crossings; a drag across them resizes the neighbours, and on a shared terminal pane resizes the pane for everyone attached.
moving a cell
A cell lifts past a threshold into FlyLayer.svelte (.oc-fly), casting --oc-shadow-lift; the insertion mark (.oc-insert-row, .oc-insert-column) shows where it will land; the page carries body.grid-dragging meanwhile. A tab dragged between components shows DropOverlay.svelte. The grip icon marks a draggable handle in a list (the slash command chips).
adding and arranging
At 1024 and wider a widget is added in edit layout alone; there ComponentsPopover.svelte and the drawer's add component menu carry one line saying where, and keep adding sessions and arranging the page (columns, rows, grid). Below 1024 they are still the restore list, the phone's show and hide. Arrangement is saved per page and, for the terminal page, per session, and syncs to every device; the live region announces what changed.
a Layout member that is down
web/src/opscenter/layouts/MemberDown.svelte (issue #424): inside an open Layout, a member whose session is not running keeps its cell and says why: asleep (a wake button), dead (recreate, through the restart picker's own recreate question) or gone. The cell's note voice, a tracked uppercase label, and the calm .modal-btn-confirm; a refusal is the coral-ruled line. A single agent's tab still shows the plain note. The row itself (.lmd, .lmd-title, .lmd-body, .lmd-error) lives in MemberDownRow.svelte (issue #791), parameterized on the member record directly, so AllDownModal.svelte (below) can draw the same row outside a grid cell.

use

detail
A mouse hovering a square, KEYBOARD focus (:focus-visible on the square) or a click or tap shows .ps-sq__detail (role="tooltip"), the status line's hairline frame raised over the chart: .ps-sq__head with the name .ps-sq__plugin and the state word in the line's own .ps-state, then four .ps-sq__fact lines: the backlog and its lag, the last delivery (ticking on the page clock), the last error with the failing count, and the runs since the server started. A touch's compatibility hover and a click's focus never hold it open: a second click or tap closes it, as do Escape, the mouse leaving the strip and a press outside. Each square is always described (aria-describedby) by a hidden .oc-visually-hidden copy of its detail, so a screen reader hears it on focus.

what it is
the wall cell
The one cell it places by default, warroom (web/src/opscenter/cells/warroom/Cell.svelte, widget core.warroom, one per surface), filling the page. It draws ONE uniform grid of equal tiles that fills the window (.ww inside a .ww-fill box; columns and rows from the tile count and the box's aspect, scrolling only below a minimum tile). A project's tiles sit together in reading order inside .ww-cells, and one outline in the project's colour wraps their union (a border on the cell edges whose neighbour is another project), with a small uppercase .ww-plabel on its first cell. The hovered tile peeks by transform only, to ONE width at every tile count that the peek zoom slider sets (0 no zoom, 50 the default, 100 the largest). Four include switches (shells, browsers, asleep, paired computers) ride the host header as .oc-chip and are also switches in the widget menu, beside the peek zoom slider (.ww-peek: a .ww-peek-label, a thin-track .ww-peek-range with a small square accent thumb, and the number in .ww-peek-val), whose menu twin is a radio set of five stops.
the tile
.ww-tile (web/src/lib/warroom/WarroomTile.svelte): a .ww-bar title strip (fixed height, hairline by box-shadow) holding the status light and a .ww-name, over a .ww-body whose read-only terminal .ww-canvas fills it, the session's full width inside a small margin, bottom rows showing. Hover (after a 250 ms rest; a touch tap is immediate) peeks the tile at the slider's width (a tile already that wide only lifts), centred and clamped inside the wall, with the terminal fitted to the session's full width inside a small margin (text never under 60% of normal, only a very wide pane clips; bottom-left of the content, whole rows), and lifts it above the wall with a strong all-around layered shadow of --oc-shadow-lift plus a minimal accent rim; a transform moves no neighbour. .ww-gone is the coral line over a session that no longer exists.
the cards
.ww-card (web/src/lib/warroom/WarroomCard.svelte) is the same chassis with a .ww-card-body of .ww-card-line facts instead of a terminal: an asleep session (.ww-dim, the asleep light, last active), a browser (its URL without the query string, live or stopped) and a paired computer whose link is down (the offline light). The wall root is .ww, styled by web/src/lib/warroom/warroom.css.

Only --oc-* tokens; the page frame and the cell frame bring the Military Terminal look.

common mistakes

  • A cell that draws its own title row or border. The frame draws them; a second one doubles the line and misses every theme and collapse behaviour.
  • A width breakpoint inside a cell. Use the cell's named width states, which follow the cell, not the window.
  • Recolouring the frame to recolour a box you see. The stat tiles draw their own edges (.oc-tile); change the thing that paints the pixel.
  • A cell that lets its body resize the terminal. A cell never negotiates the session's size.
