dialogs

A dialog is for a bounded decision: create, configure, confirm. It dims the page, holds one focus trap, closes on Escape, and gives focus back to what opened it. The restart picker is the reference: title-row strip, one line per option, the footer's buttons, nothing else.

anatomy
Overlay .modal-overlay (fixed, --oc-backdrop, centred). Panel .modal-content (--oc-ground-raised, 1px --oc-line-panel, --oc-radius-sm) with padding: 0 and a width cap (the picker is 500px). Head strip: the title-row recipe with a tracked accent VERB, the object's name in the primary tier, and a state marker at the right. Body: the options. Footer: .modal-footer with the arm box on the left and the buttons on the right (buttons).
copy
One header line, one line per option, a short tag only where the outcome differs. No intro paragraph, no per-option explanation, no footer note (Alex, #558: "remove useless text. streamline it. effeciency is god."). Catalog keys: session.restart.picker.*.
launch choice
The restart picker's choice is the ONE launch control (web/src/lib/launch-picker/LaunchChoiceHost.svelte over LaunchChoice, mounted into .restart-picker__choice; the dropdown is documented in the launch picker): the profile dropdown preselected on the "launched with" row, and under it, for a claude row, the account disclosure ("choose account", the account dropdown and the box "always launch this agent under this account"). A saved account opens the disclosure ticked; collapsed sends no account. A row the server or the arm box refuses is listed, dimmed and cannot be chosen; Escape with the list open closes only the list. The dialog reads and steers it through the handle mountLaunchChoice returns. Catalog keys: launch_picker.*, session.restart.picker.*.
legacy chassis
client/css/styles.css owns .modal-overlay, .modal-content, .modal-header, .modal-body, .modal-footer, .modal-input and the buttons for twenty-two dialogs across both trees. Its .modal-header (plain bold 1.3rem, the title is NOT the accent) and 31px padding are the older look; a restyled dialog sets padding: 0 on its content and adds the head strip, the way text-prompt-modal.css and session-restart-picker.css do.
title row (Joe, 2026-10-28)
Every dialog title strip is .modal-titlerow (client/css/modal-titlerow.css), copied from the restart picker's head: --oc-titlerow-h (37px) tall, 14px side padding, --oc-ground-titlerow, the hairline as an inset shadow. The restart picker, the confirm dialog, the reopen offer, the media lightbox bar and the colour and icon pickers wear it, and .text-prompt-modal__head is listed in the same rule for the dialogs that already carry that name. A dialog adds only a gap or a justify on its own head class; a different height or padding is not a sixth copy of the strip, it is not a title row.
glow (issue #918)
client/css/modal-glow.css gives every dialog on this chassis the same border shimmer a popup menu wears (menus and popups), scaled up: roughly 1.3x the menu's blur/offset and about ten more points of colour-mix intensity, since a dialog is the larger surface. It targets .modal-content alone, so it reaches every dialog on this page with no markup change - the reference dialog above, the confirm dialog, the text prompt, every compiled ModalShell dialog below, and the "?" help panel. It also reaches one surface that predates this chassis and is not .modal-content: the help panel's media lightbox (.sidebar-help__lightbox-body). Its sheen is the compositor-only turn of popup-focus-turn (popup-focus.css): a conic square that rotates with transform inside a masked 1px host, so an open dialog costs no style or paint work per frame. The host is one child, <span class="mg-sheen" aria-hidden="true">, that client/js/modal-ring.js appends to every .modal-content and lightbox body as it is added, so no dialog builder writes it and a new dialog needs nothing. The keyframes are this file's own (modal-glow-turn); the duration, easing and angular span match the menu exactly, so the travelling sheen is identical in character, not a lookalike; prefers-reduced-motion (and the animations setting) drops the sheen and stops the turn the same way the menu does. It does NOT reach the file editor (.config-editor-modal-content, full screen, no edge to draw) or the file-picker drawer (.config-editor-picker-content, a right-edge drawer, not a floating card).
focus
Legacy: window.ModalStack.trap(overlay, opts) (client/js/modal-stack.js) is the one focus-trap, Escape, Tab-wrap and focus-restore contract; stacked modals get .modal-stack--covered and the page .modal-stack-locked, and Escape reaches only the top entry. Compiled: ModalShell does the same for itself.
access
role="dialog", aria-modal="true", an aria-label or aria-labelledby naming the object; first control focused on open; Escape cancels unless the dialog is busy; the overlay click cancels; focus returns to the opener.

ModalShell
web/src/lib/launchpad/ModalShell.svelte: the one compiled dialog frame. Props title (already translated), children and footer snippets, dismissable (false while busy), onCancel, and for a dialog with its own card look head (a replacement title strip), an optional footer (absent: no footer row), contentClass (extra classes on the panel) and any other attribute, which lands on the overlay (the send-to and move-folder dialogs are built this way). It carries no style of its own and borrows the chassis classes by name, so it changes with the legacy dialogs. It takes focus on mount, traps Tab, handles Escape itself and restores focus on unmount.

overlayClass and head
Two optional ModalShell props for a dialog with a scoped look: an extra class on the overlay, and a snippet that replaces the plain header row. Absent, the chassis is unchanged. The legacy App.showConfirmModal (client/js/app.js) carries the matching overlayClass parameter, but since issue #864 it no longer gates the header: every showConfirmModal dialog gets the shared, unscoped .modal-titlerow / .confirm-modal__verb title-row strip and the confirm-modal overlay class UNCONDITIONALLY (client/css/confirm-modal.css). overlayClass stays available only as an extra class for a caller that needs further one-off scoping of its own - no current caller does.
mounting
A dialog is mounted on demand onto document.body through the launchpad's modal host (web/src/lib/launchpad/modals.ts) and unmounted when it resolves. Never mount one at load: it takes focus the instant it mounts.

common mistakes

  • Restyling only the header. PR #598 changed the title and left the rounded, accent-ringed field and the solid button; rejected. Restyle the whole dialog from the reference.
  • A second confirm. The ticked arm box IS the confirmation for a live kill; no modal follows the click (Alex, #441).
  • A layout jump inside the dialog. A centred dialog that grows moves every row above the change (#592).
  • Two Escape listeners. A dialog over a screen that owns a document Escape listener must take focus on mount so its own handler sees the key first; stacked legacy dialogs register with ModalStack.
  • A dialog for navigation. Routine navigation is a screen or a drawer; a dialog is a bounded decision.
