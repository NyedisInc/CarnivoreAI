making a new icon or component that fits

When the thing you need is not on this page, build the smallest thing that looks like it was always here: same grid, same stroke, same tokens, same states, same voice.

a new icon

  1. Check first. Scan the icon set and the glyph table. A near match with a clear meaning beats a new drawing. Never draw a second robot, kebab or provider mark.
  2. Draw on the grid. A 24x24 box, 1.5 stroke, stroke-linecap and stroke-linejoin round, no fill unless it is a deliberately solid symbol, 2px of clearance to the box edge, optical weight matched to terminal and folder beside it. A path borrowed from an open set (the recycle mark is lucide's) says so in a comment.
  3. No colour. currentColor only; the button sets color from a token.
  4. Add it once. Compiled: a key in web/src/opscenter/ui/icons.ts, named for what it IS (music, vinyl), not for where it is used. Legacy and shared: records in client/js/icons/glyphs.js on the 16 grid, drawn by both renderers.
  5. Size by context. 14px in a tab, 16px in chrome and menus, 20px only for the header kebab and the rare larger mark. An icon-only button gets an aria-label and a title from the catalog.
  6. On and off. A toggle icon is grey and still when off, coloured with a subtle living detail when on (the cup's steam, the switch's sparkle), and still again under reduced motion.
  7. Check it. It appears in the icon set the moment it is added. Look at it under three themes at 14 and 16px beside its neighbours.

a new component

  1. Find its family on this page. Every component is a variation of one here: a panel, a row, a menu, a dialog, a field, a chip, a cell. Start from that family's markup and classes.
  2. Build it in web/ as a Svelte 5 component with typed props, one job, documented (a one-line description, typed inputs, an example when usage is not obvious). Put it in the folder of the surface that owns it, or in web/src/opscenter/ui/ when two surfaces share it.
  3. Style with tokens only, in the component's scoped <style>: grounds, lines and text tiers from the token table, the title-row recipe for a header, 1px hairlines, 2px corners on controls, --font-mono, the cyan focus outline. Where a scoped reference rule cannot be reached, restate it and name the source in a comment.
  4. Every state: default, hover, focus-visible, active, disabled with its reason, busy with its verb, empty, error, unknown. A state change never moves layout.
  5. Every width: at 390px no horizontal scroll and 44px targets; at 2560px capped and centred.
  6. Register it: its file and classes in client/style-guide/registry.json under the section that documents it, and a live specimen in that section's fragment (a sg-live-* container plus an entry in web/src/style-guide/main.ts) when it has props that can be fed a fixture without touching the API.

naming

  • Components are PascalCase for what they are (MusicTrackRow, MusicHeader), in the folder of the surface that owns them.
  • Classes: a short block prefix per surface, BEM-style elements and modifiers (music-row, music-row__title, music-row--playing). Reuse .pl-* and .modal-* rather than renaming them.
  • State is a data-* attribute or a class: directive, never a global state class.
  • Catalog keys name meaning, flat and dotted: music.row.playing, not music.green_label.
  • Tokens are never added by a feature; tokens.css is the palette. A local alias block at the screen root (--music-* from --oc-*) is fine and is the ledger's pattern.
