motion and focus

Two things animate by design: the breathing ring of a running session's light, and the popup focus sheen. Everything else moves only enough to explain a change, and every motion stops for prefers-reduced-motion.

under prefers-reduced-motion: reduce the three motion tokens resolve to 0ms.

the ring
A running session's light breathes; that is the only perpetual animation in a list. It stops for reduced motion and holds at full brightness. See the status light.
popup focus
Every floating menu and the selected terminal cell wear .popup-focus (client/css/popup-focus.css): a top-down 1px border drawn by background layers, a short bright arc that travels once around it every 6 seconds, a 5px accent glow and two flat black drop shadows. Opt in with the class; never copy its declarations. A surface that needs its own edge colour sets the --pf-* inputs (the active terminal cell sets its session accent). A surface that stays on screen, the selected terminal cell, adds popup-focus-turn and one <span class="pf-sheen" aria-hidden="true"> child: the arc then rotates with transform only, behind a static 1px mask, so an idle selected terminal costs no layout or repaint (#1809). Reduced motion shows no sheen at all, not a parked one.
transitions
Colour, background and border colour on hover over --oc-motion-fast, ease. No transform on hover, no lift, no scale (the old .modal-close:hover scale is legacy). An entering dialog fades 0.2s.
on-state marks
A toggle icon that is ON may carry a subtle living detail: the keep-awake cup's rising steam, the auto switch's sparkle. Grey and still when off; coloured with the small animation when on (Alex, #151 and #559). Each respects reduced motion.
focus
Focus is the element's OWN border, a little brighter, same width, no shadow (Alex (example-owner), 2026-09-27, reversing the 2px cyan outline, then softening an intervening "+1px bolder" pass the same day: "this is way too bold, scrap the bolding part and just make the color of the outline get a little brighter of the same color"). One shared rule in web/src/opscenter/focus.css does it for every :focus-visible element in both trees (a clicked text field matches too): no outline; the edge colour is the element's border colour (--_bd, else currentColor) mixed toward --oc-focus-lift (white on a dark ground, black on a light one) by a small amount, so the box never changes size and the shift reads as subtle. A control with a reserved but invisible 1px border shows the same brightened hairline; a control with no border reserved at all has nothing to colour. A component whose border hue differs from its text sets --_bd to its border token; a field inside a frame puts oc-focus-host on the frame so the frame lights instead. Never write a per-component focus outline or ring, and never add a shadow or extra width to make it more visible. A manager card (.mgr-card, the widgets page) lights as a whole when its name control .mgr-card__open takes focus.

animation pause

use
Every infinite animation animates transform or opacity only, so it runs on the compositor. One listener (client/js/animation-pauser.js) marks an animated element that left the viewport with data-anim-offscreen, and client/css/animation-pause.css pauses it (animation-play-state, never animation: none, so it resumes in phase). The same file pauses everything under a visibility: hidden cover: body.menu-page-open over .screen, .header and .config-editor-picker-overlay, an inactive tab body (.oc-tabpane-hidden) and the terminal parking shelf. A new cover that hides a subtree with visibility: hidden is added to that list. Sidebar rows are not special-cased: every row's status light, effort mark and keep-awake steam animate while the window is focused, and calm (below) holds them when it is not.

animation types

use
Every animation belongs to one recognizable type (status lights, avatar spiral, terminal ring, dialog glow, effort badges, drawer bands, sparks and steam, busy pulses, attention cues, swarm characters, pop-ins, transitions, layout moves, theme backdrop, cursor blink; the ids are ANIMATION_TYPES in web/src/lib/motion/animation-types.ts). Settings > appearance can switch each off in one browser: data-anim-off="<ids>" on the root, kept in localStorage. client/css/animation-types.css is one rule group per CSS type (animation: none !important; transitions drop transition). A new animation joins an existing type's selector list there, or becomes a new id in both files; a JS loop reads the same attribute.

effort level

low medium high xhigh max ultracode
use
The reasoning effort a session runs at (issue #852): the foot bar's effort text and the drawer's agent robot both wear .effort-level .effort--<level>; the drawer robot also wears .session-sidebar-row-model (an xhigh robot also carries an .effort-fx span, the three sheen windows). Both read one mapping, effortClass(effort) (web/src/lib/effort/effort-level.ts) or EffortLevel.className(effort) (client/js/effort-level.js). low yellow, medium green, high cyan, xhigh light purple with a shimmer (an opacity pulse over a glow; on the robot a bright copy of the drawing revealed through a sliding window), max a rainbow colour cycle (coral, green and cyan copies cross-faded by opacity), ultracode deep purple with a shimmer and two twinkling sparkles.
a record, never a default
The level is what the harness wrote (running_model_effort on the listing WRAPPER, effort on the token usage payload). Unknown or absent writes no class, and the element keeps its own colour.
motion
On the agent robot, high and xhigh are a steady colour (high its own cost tint, xhigh light purple) with a moving bright sheen (a mask sweep, effort-sheen), never a colour flash. Otherwise a filter and a colour, never a text gradient, so the same class moves an SVG robot stroked in currentColor. Under prefers-reduced-motion every colour stays and every animation and sparkle goes.
themes
--oc-yellow, --oc-green, --oc-cyan, --oc-coral and the two derived purples, --oc-purple-light and --oc-purple-deep.

common mistakes

  • A focus ring of any colour, or any added thickness. An accent ring made PR #598's dialog read as a red-outlined box, and the cyan ring that replaced it was "annoying" (Alex (example-owner), 2026-09-27); the "+1px bolder" edge that replaced THAT was itself "way too bold" the same day. Focus is the element's own edge, a little brighter, same width, from focus.css; never add an outline, a ring, or a shadow per component.
  • Waiting on requestAnimationFrame for work a hidden tab must still do. A bare rAF never resolves in a background tab (gotcha 9); race a timer (client/js/terminal-layout-wait.js).
  • A new perpetual animation. One breathing thing per list is the budget. A second one competes with the only signal that means "running".
  • A parked sheen under reduced motion. A sheen frozen at 0deg reads as a rendering fault; remove it.
