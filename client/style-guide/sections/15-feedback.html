toasts, notices, empty, loading and error states

Feedback says what happened, in words, where the user is looking, and gets out of the way. A toast is for something that happened elsewhere; a notice strip is for something about this screen; an inline line is for a field or a row. Loading is a word, never a spinner. Empty is a sentence and, when there is one, the action that fills it.

use
Something happened in a session you are not looking at: a permission request, a finished turn, a notification. Toasts group per session and kind (toast-grouping.js), show a ×N count, collapse into an overflow row when there are too many (fewer and full width under 640px), (the clickable card rule lives in toast-collapse.css). Clicking a toast navigates to its session (toast-navigate.js).
not for
A field error, a confirmation of the user's own click on this screen, or anything the user must act on to continue: those are inline or a dialog.
severity
data-severity="3" (blocking, a permission) is an alert exempt from the cap; lower severities are status. The kind's marker is a ::before on the title keyed by data-kind.
title icon
The auto-sleep toast (kind="AutoSlept", issue #690) is the one exception to the ::before marker above: its title is prefixed with a real .toast__title-icon node carrying the app's own reused sleep glyph (SessionRowMenuIcons.svg('sleep', 13) - the same crescent moon as the row menu's sleep item and the status LED's asleep state), so it can paint with currentColor and follow the title's own --oc-text-primary instead of a kind carrying its own hardcoded color.
action
A local card (local: true, raised from this browser) may carry one action: action_label plus on_action, drawn by toast-render.js as the quiet .modal-btn-secondary with .toast__action. Pressing it runs the action and retires the card. The widgets page's "undo" is the user.
themes
The card is --oc-ground-card, the one ground every theme lifts off its own terminal, so a toast reads over output in all 40 themes. A session toast can take its session's theme (data-themed="1").
access
The container is a live region; each card is focusable, its dismiss button labelled. Muting never suppresses status events; viewing never resolves an open permission.

use
Every card whose toast carries a registered notify_type gets .toast__mute at its bottom right, drawn by the ONE shared renderer (client/js/toast-render.js calls window.NotifyMute.attach), never per call site. Action feedback cards (no type) get none.
how
The button opens .notify-mute-pop, which wears popup-focus and holds two .notify-mute-pop__item rows: "mute here" (this device; a phone also stops its own push) and "mute everywhere" (every device and destination). A mute confirms with a NotifyMuted card whose one action is .toast__mute-undo, a quiet outline like .modal-btn-secondary. .toast--mutable gives a one-line card room for the x and the control.
never
Never key a mute on the message text, and never let it touch the status lights: muting hides the pop-up and outside delivery only.

waiting line
.toast-waiting reads "N sessions waiting" when more than one session holds a card. It is a status line, not a control: the title-row label (small tracked capitals in --oc-orange) with a hairline under it, after the dismiss-all control and before every card.
not for
Deciding which events notify. The style changes presentation only; the watcher raises exactly the same records.

notice strips and banners

live region
deep link
A link to something that no longer exists lands on home with a notice strip saying why, never a silent bounce (client/css/deep-link-notice.css, .deep-link-error__text, .deep-link-error__dismiss).
new version
VersionBanner.svelte (.vb-banner): a reload offer when the server moved on, with reload and dismiss (#576). It grows a collapsed what-is-new list (.vb-news, .vb-list, .vb-row, .vb-tag, .vb-item, .vb-where, .vb-label, .vb-toggle, .vb-head, .vb-list--open) fed by GET /api/v1/whats-new (#1196). The version chip in the footer is .version-footer.
offline marker
perf overlay
PerfOverlay.svelte (.perf-ov, .perf-ov__bar, .perf-ov__title, .perf-ov__toggle, .perf-ov__grid, .perf-ov__label, .perf-ov__list, .perf-ov__ms): a developer-only panel in the bottom right, mounted only while the dev perf setting is on. Title-row strip with the one orange label, mono numbers in a two-column grid, hairlines between regions, and a quiet hide/show toggle. Never shown to a user with the setting off.
terminal notices
TerminalSizeNotice.svelte (the pane is sized by another viewer) and TerminalStartupNotice.svelte (the startup command could not be sent) sit over the terminal as one quiet line with a dismiss; they never cover the prompt.
status pill
The legacy app-wide status line (FabMenu.notify(message, level), .fab-menu-notice) is the single channel for a short system message such as a refused theme script. Do not add a seventh message shape.

loading
The word, in the secondary tier ("reading...", "installing"), in the place the content will appear. No spinners, no skeleton shimmer: shimmer would be a second animation competing with the running light. A button that is working says its busy verb and is disabled.
unknown
error
Inline, next to what failed: --oc-ground-raised line, 2px --oc-coral left edge, primary text, 11 to 12px, overflow-wrap: anywhere (the base State error, live on the "work" card in the provider ledger). Say what failed and what happens next. Never print a server's raw error object; detailOf in opscenter/api/auth.svelte.ts extracts the sentence. A card whose data is stale keeps its last good answer and says how old it is.

common mistakes

  • Narration. Poller chatter and recommendations were removed from the providers panel: show data, not commentary. A quiet footer at most.
  • A toast for a field error. It disappears and hides what to fix.
  • "Not loaded" treated as "empty". A deep link that raced the list load bounced home (#543). Await the newest load; never read absence before the first answer.
  • A spinner. Words, in place.
