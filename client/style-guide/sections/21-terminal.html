terminal chrome and the prompt bar

The terminal is xterm.js painting a tmux pane. Everything around it (the prompt bar, the head row, the status bar, the tools, the key bar, copy and paste) is chrome that must never cover a glyph, never resize the pane by itself, and never take input meant for the terminal.

mascot overlay
A theme may name a mascot sprite in its theme.json; client/js/terminal-mascot.js finds Claude Code's Clawd block in the top of the xterm buffer and pins .terminal-mascot (client/css/terminal-mascot.css) over exactly those 9 by 3 cells with an xterm decoration. The sprite is artwork and may carry its own colours; the CSS holds none. No match leaves stock Clawd, and the pane's bytes are never touched.
head row
A tabbed component's head row is the last-prompt bar (#533): TerminalHead.svelte, PromptHeader.svelte, PromptHeaderControls.svelte, PromptRail.svelte, PromptTick.svelte. The floating prompt header sits on --oc-ground-card (the one ground every theme lifts off its own terminal) with a lit lower edge (--oc-strip-edge) and a faint glow (--oc-strip-glow), because a ground step alone does not stick out on the darkest themes (Alex, 2026-09-21: "maybe a color glowing dropshadow (minimal)?"). INLINE in a tabbed component (.prompt-header-root--inline) it joins the tab band instead: the same --oc-ground-titlerow as the active tab, one continuous surface with no divider under it (Alex, #606 follow-up). It sits FLUSH under the strip now, 0px gap (Alex, #627: REVERSES the 5px spacer #594 put here, removed entirely once the tool icon group moved off this row - see "tools" below), and spans the row's full content width, since it no longer shares the row with anything else.
tools
TerminalActions.svelte and TerminalUtilities.svelte: session skills, session plugins, files, search, notes, theme, the background picture (.tbg-open), bookmarks and keep awake, sleep and the size crown as 15px icons in the bar (toolbar.ts's width ladder), folding into the session kebab menu one at a time as the cell narrows, least used first, search and files last (Joe (ccsliinc), 2026-10-21, reversing #959, #1551 and the 2026-10-14 kebab moves). The kebab (.cell-options) matches CellMenu.svelte's look and behaviour - role="menu"/menuitem, arrow-key navigation, focus-on-open, focus returned to the trigger on close - rather than a bespoke menu. In the tab strip (.oc-frame-strip) every control, the bookmark key (.oc-ibtn) included, is exactly as tall as the tab body beside it. IN A TABBED COMPONENT THIS GROUP RENDERS IN THE TAB STRIP NOW, NOT THE HEAD ROW (Alex, 2026-09-25, #627, superseding "move all the icons down to the right of the arrows" from the #533 prompt-bar merge): right-aligned after the tabs and the "+", vertically centred with them, on the strip's own ground (--oc-ground-tabstrip) rather than the active tab's - TerminalHead.svelte writes the same snippet it would otherwise render inline to a new frameHeader.tools slot (frame-header.svelte.ts), which CellFrame.svelte renders inside .oc-frame-strip. The untabbed head row is unaffected: it keeps its icons inline, unchanged.

opened pages
A page opened for the owner (Joe (ccsliinc), 2026-10-11, docs/browser-pages.md): a Task Manager artifact or the app's own pop-out page is a ROW in the left sidebar's browser list (the browser row with a document mark, data-browser-state="page", the docs icon, no rename, a "close page" menu item) and shows FULL SIZE in the browser screen where a session's terminal shows. The body (PageFrame.svelte) is one frame filling the screen with no card or border of its own (.pf-frame); an artifact's is the artifact dialog's locked-down frame, sandbox="allow-scripts" and never allow-same-origin, with its light canvas (.pf-frame--sandboxed); a page that cannot be framed shows .pf-note. Every browser or page row has a "pop out" menu item and row key: a page opens in its own tab; a proxy browser asks where every time (PopOutChoice.svelte, in dialogs), the proxy itself opening in the pop-out page ?browser=<id> (BrowserPopout.svelte: .bp, .bp-body, .bp-notice, the one widget header over BrowserView).
opened files

themes
The terminal wears its session's theme (pin, then project default, then global) on its own container through [data-session-theme]; the chrome around it stays on the global theme. terminal-carnivore.css keeps the header and sidebar Military Terminal whatever the session theme is; session-theme-tint.css draws a session's pinned accent where it is listed.
layout command bar
LayoutCommandBar.svelte (issue #837, #943): the strip across the top of an open Layout, in flow in #layout-command-bar above the grid and empty on every other view. The Layout's name is a tab (.lcb__tabs holding LayoutTabs.svelte, issue #1223: the terminal tab strip itself, TabStrip.svelte with no component icon, its tabs the one key (.oc-tab, the accent on top when active, each name in its Layout's colour), a close .oc-tab-x while more than one is open, and the .oc-tab-new plus that opens the one menu of the Layouts not yet tabbed; the arrows move between tabs and Enter opens one; the list is per device and a close never deletes the Layout); then one box, right-justified at half width inside .lcb__slot (.lcb__box, the catalog's .oc-field, oc-focus-host, so the box's own edge brightens, softly, while its field has focus) holding TWO mode buttons on its left (base quiet IconButtons, glass then >): the active mode's icon is bright and the other dim, and each selects its own mode. The field is a textarea that grows downward over the page to show wrapped text. Search drives each terminal's own search (layout-search.svelte.ts drives each SearchController, never a second engine); command sends the line plus Enter to every live terminal whose toggle is on through POST /api/v1/layouts/{uuid}/broadcast. Search mode adds the count (.lcb__count) and the prompts-only switch (the single session panel's own glyph and the same per-device value) and previous/next. Command mode adds a small base Button (data-bar-tool="recipients"), "to 2 of 3", which opens the recipients menu (the one menu engine, CascadeMenu, an on/off check per terminal) and turns yellow when nobody would receive it (restored 2026-09-29, reversing that part of issue #1016); each terminal's own > toggle sets the same value. A clean send says nothing further - Enter is already the confirmation; a skip or a failure still reports in the result line (.lcb__line, which carries .lcb__line--empty and leaves the flex flow entirely when there is nothing to say, so its own gap never reserves trailing space after it). Below 600px the extras and the result line give way; Enter and Shift+Enter still walk. While the desktop drawer is collapsed to the mini rail (body.session-sidebar-railed), the box right-justifies to the header's right edge instead of sitting flush left of the name. In command mode a line that starts with "/" (Claude Code) or "$" (Codex) opens the skill list (.lsk, LayoutSkillMenu.svelte) under the box: .lsk__item rows with the name (.lsk__name), a scope tag (.lsk__scope, global or project) and the one-line description (.lsk__desc); the lit row (.lsk__item--active) wears the accent border like a recipients-menu row. Global skills always, project skills only when every terminal the line would reach has them (GET /api/v1/layouts/{uuid}/skills). Up and Down move, Tab or Enter insert, Escape closes.
broadcast toggle
LayoutCellMarks.svelte: a > in each member terminal's tool group (a base quiet IconButton, pressed - issue #1021), pressed means on, the default and a broadcast skips it when unpressed. NO BOX AT REST in either state: on reads the same colour as the row's other tool icons (--oc-orange), off dims the glyph (--oc-text-dim, the tab strip's own idle-icon idiom - issue #936). Hovering either state may paint the sibling tool buttons' own hover box (border plus ground fill), same as any other tool icon; keyboard focus carries no rule of its own and is handled entirely by the one shared focus.css rule. Stored with the membership (PUT /layouts/{uuid}/members/{session_uuid}/broadcast), so every device agrees. While the bar searches, the terminal's own count sits beside it (.lcm__count, .lcm__count--current on the terminal the walk is on).
solo terminal window
The desktop app's native terminal window (R1-12, #2330; docs/desktop-app.md) is this same page at /?solo=<row id>: client/js/solo-window.js stamps data-solo on the root, the agents drawer, its rail and the home screen never appear, and the one pane is the page's own. While the row has no live session, SoloPanel.svelte (.solo) covers the window with a title row (.solo__bar, one small tracked accent label .solo__label and the session name .solo__name) over a body (.solo__body) of at most one shared .oc-btn (wake, reopen or close this window) and the server's own sentence when it refused (.solo__note, in the coral token). Four states: looking for this session, asleep, no longer running, ended. The window never closes itself and never shows another session.

rules the terminal chrome may never break

  • A hidden tab does not vote on the pane's size (pty_resize carries hidden: true, Alex 2026-09-23). A flag, never a faked size.
  • Claim input at the gesture, check it at the write (terminal-input-ownership.js); a stale navigation token discards silently.
  • The left inset is --oc-terminal-inset (8px) and never more than 16: above that, glyphs clip.
  • A bare requestAnimationFrame never resolves in a hidden tab; race a timer (gotcha 9).
  • Nothing overlays the prompt row; a notice sits above the output, never on the input line.

crosstalk cards on a terminal (core since #1899, formerly the xtalk plugin)

The crosstalk cards (a Settings switch under Terminal, off for a new install) draw a FROM card on the terminal a crosstalk message was delivered to and a TO card on the terminal that sent it. The server pushes one crosstalk.card frame per delivery and nothing reads the terminal or its scrollback. web/src/lib/crosstalk/terminal-cards/CardStack.svelte owns the markup, web/src/lib/crosstalk/terminal-cards/terminal-cards.css the [data-xtalk-card] and .xtalk-layer selectors, a hairline, a 3px square-cornered left bar in the accent for FROM and the confirm green for TO, a tracked uppercase direction, and tokens only. The whole card is one button: click to dismiss; it also expires on its own after twenty seconds, unless the keep cards until dismissed setting is on (off by default): then the cards stay, per session, while the page is open, and the layer takes the modifier .xtalk-layer--keep (only the card column, scrollable). The layer sits over the terminal in the cell's enclosing box, never inside the pane, so it takes none of the terminal's input.

common mistakes

  • A bar icon that breaks the fold width. The cup moved show-everything from 600 to 640px.
  • A strip on the terminal colour. On carnivore four grounds are the same #02161e; a strip painted on any of them reads as output. Use --oc-ground-card.
  • A session theme painting the page. A pin reaches its own subtree only (#318).
  • Treating a status grey flash as a UI bug. It is the watcher being honest under load (#524).
