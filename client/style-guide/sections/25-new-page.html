building a new page

A worked example: "make a new page in Carnivore for Music". Every step names the file to copy. Follow it and the page looks exactly like the ledger, the catalog and the themes page, under every theme.

0. decide what it is

  • A full page you open, read and close (a library, an account list): an OVERLAY SCREEN like the ledger. This walkthrough.
  • A box on the dashboard beside running sessions (now playing): a CELL KIND on CellFrame (step 10).
  • A bounded decision (pick a track, confirm a delete): a DIALOG on ModalShell (dialogs).

the steps

  1. Intake. Run the work skill (.claude/skills/work/SKILL.md): search issues, file or reuse one, claim it, work in a worktree under dev-worktrees/cloudecode/. Read this guide's principles, then the ledger's files.
  2. API first. Every action the page offers is an authenticated route before it is a button: src/api/music_routes.py, included by one line in the src/api/routes.py aggregator. The page is a client of those routes and of nothing else.
  3. The container. Add <div id="music-screen"></div> to client/index.html beside #ledger-screen. The id is a contract; nothing else mounts there, and the container carries no class.
  4. The component, in web/. web/src/lib/music/MusicScreen.svelte, copying web/src/lib/ledger/LedgerScreen.svelte: 
    {#if open}
  <div class="pledger music-screen screen" role="region" aria-label={t('music.screen.title')}>
    <MusicHeader count={tracks.length} onBack={close} {t} />
    <div class="music-scroll">        <!-- THE ONE SCROLLING BOX -->
      <div class="music-main">        <!-- capped at 1680px, centred, --pl-gutter padding -->
        <section class="pl-panel" aria-labelledby="music-now">
          <div class="pl-titlebar"><h2 class="pl-title" id="music-now">{t('music.now.title')}</h2></div>
          ...
        </section>
      </div>
    </div>
  </div>
{/if}
    The page is the shared frame, Page (web/src/opscenter/ui/Page.svelte, rules in web/src/opscenter/page.css): .oc-page is fixed from var(--overlay-top), z-index 40, column flex, and the page supplies only its body inside .oc-page__body. Never write a fixed root of your own. A search bar is SearchField in the bar snippet; the single @media (max-width: 1023px) step lives in page.css.
  5. The header. Page draws it: the title, a count, the one confirming action in the actions snippet, a quiet close .oc-btn. A dialog opened from the page uses the picker's buttons (buttons).
  6. The body. Compose what this guide shows: panels with title rows (panels), cards in repeat(auto-fill, minmax(min(100%, 340px), 1fr)) when each item is its own decision, a DataTable when items are compared (tables), StatusLed and SessionFace wherever a session appears, CascadeMenu for any menu, the field and switch from forms, the empty, loading and error lines from feedback. Each section of the body is its own card under its own strip, 24px apart, and the one that holds the next step is the primary one (a column of sections).
  7. The host. web/src/lib/music/screen-host.ts, copying web/src/lib/ledger/screen-host.ts: ensurePanel('music-screen', MusicScreen, {}), openMusicScreen() and closeMusicScreen(), the hash #music read once after whenLegacyBootComplete() and then on hashchange. Wire it from web/src/main.ts the way the ledger's is.
  8. Navigation. Add a row to RAIL_DESTINATIONS in web/src/opscenter/shell/rail-items.ts: { id: 'music', icon: 'music', labelKey: 'opscenter.nav.music', hint: 'm', run: () => void openMusic() }, with openMusic beside openThemes in web/src/opscenter/api. The agents drawer's menu tab draws it; the hash is the deep link.
  9. Strings. Add every string to client/js/i18n/catalog.en.js as flat dotted keys that say what the string MEANS (music.screen.title, music.empty, music.error.read), data only, lowercase, no dashes, no emoji. Read them with t(); keep the key list in a MUSIC_KEYS object in the model file the way LEDGER_KEYS is.
  10. Tokens and icons. Use --oc-* and the --pl-* aliases; add no colour. A new icon goes into web/src/opscenter/ui/icons.ts on the 24 grid (making a new icon). If a meaning truly needs a colour no token carries, derive it with color-mix() at the screen root and say why.
  11. A dashboard cell instead. Add a record to web/src/opscenter/engine/meta.ts (title key, icon, icon tone, size ladder with named width and height states, phone order), a web/src/opscenter/cells/music/Cell.svelte that draws only its body, and its entry in cells/registry.ts. CellFrame gives it the title row, collapse, menu and every theme.
  12. This guide. Every new Svelte component and every new class goes into client/style-guide/registry.json under the section that documents it, in the same change; venv/bin/python3 -m tests.helpers.style_guide_inventory prints what is missing. A pattern this guide did not have gets a section entry (when nothing fits).
  13. Tests. A vitest for the model (music-model.test.ts), a render test for the screen (ThemesScreen.render.test.ts is a model), the style guide drift test, tests/test_no_remote_assets.py, and a browser verify script under scripts/ (the verify_terminal_tabs.py family) that loads the page on a leased server, asserts the concrete computed properties (outlined actions, 2px corners, cyan focus, the title row's inset rule) under three themes, and is proven able to fail. Client-only diffs run the client tier, never the full suite; a server route change runs the full suite.
  14. Build and look. cd web && npm run build (leave client/dist unstaged on a branch), scripts/web-build-check.sh --branch, python3 scripts/js_syntax_check.py on any legacy JS you touched. Lease a server (scripts/testsrv lease), render at 390px and 1600px under carnivore, codex and one more, and put the page beside the ledger before calling it done.

the phone header (below 768px)

Binding for every page (Alex (example-owner), 2026-10-04, "i like 2 + 5", docs/DECISIONS.md; it supersedes the 2026-10-03 three-row header): on a phone the page's header is ONE 56px bar on the 16px gutter and no bar holds a lone small control. Left to right: the back arrow (.oc-titlebar__back, arrow-left, 40px, the arrow tip on the gutter) that runs the page closer, the omnibar frame (.oc-titlebar__omni, 44px, one hairline, two lines: the title as a 10px tracked accent overline, then a magnifier and the page's ONE search input, .oc-titlebar__omni-row), then the filters that fit as a joined 44px control and ONE view flip (.oc-page__flip, 44x44, shows the current view and names the switch) inside .oc-titlebar__controls. Page draws no close button and the shell strip is not drawn. A page with no search shows the title alone. A page may pass icon to draw its own 14px icon inside the heading, left of the title (.oc-titlebar__icon; the warez page wears its floppy). Filters that would squeeze the frame under about 150px, and the page's own actions, take ONE row under the bar (.oc-page__bar, .oc-page__tools--end); a tabbed page puts its tab row there (settings merges its section picker into the row as the first cell, .st-picker). Keep ONE search input in the DOM and move it, never duplicate it. A page built on ManagerFrame inherits all of it; a hand-built page passes search (and controls) to Page while viewport.narrow and draws the same field in its bar otherwise. Targets stay 40px or more and the bar's, the flip's and the cards' right edges share a line within 1px.

The rows under the bar SCROLL AWAY (layout 5, same pick). Page puts the tab row and the bar in ONE wrapper, .oc-page__away, sticky under the sticky title bar; scrolling down slides it behind the bar by a transform (the scroll area never changes size, so nothing flickers) and the bar casts the lift-shadow token while it is away (.oc-page--away on the root). A scroll up of about 16px, the top of the page, focus inside the rows or a click on them brings it back; content that overflows by less than the rows' own height never hides it; reduced motion is instant. The rules are the pure client/js/scroll-away.js, wired by web/src/opscenter/ui/scroll-away.ts. A host that embeds screens (warez) takes their search, filter row and flip into its own Page (the searchSlot, barSlot and controlsSlot props) so the rows slide as one, and its sign-in act (.warez-act) is the last control of the bar's one sideways row, never a row of its own and never header. Desktop never hides.

done means

  • No colour literal in the diff; every colour an --oc-* token or an alias of one.
  • Every string a catalog key; no em dash, en dash or emoji.
  • Every action behind an authenticated route.
  • At 390px the header follows the phone header rule above; no horizontal scroll; content capped and centred at 2560px; 44px targets under 1024px.
  • Screenshots under three themes, one of them light, that look like the ledger.
  • Cover the body text and every section is still countable and nameable from its strip: a card each, 24px apart, one primary section that holds the next step (a column of sections).
  • Every view that opens has its own close or back at its top and foot, and Escape closes it; every set of marks has a key in view.
  • The registry and this guide updated; the drift test green.
