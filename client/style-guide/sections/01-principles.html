principles and the military terminal look

The canonical reference for how Carnivore looks. Every example is the real component in the stylesheets the app ships (the same list and order as client/index.html), in the theme picked at the top. Read this, then the section for the component you are touching, and copy what it shows.

the rules that bind every surface

  1. Colour is --oc-* tokens only. Never a hex, rgb() or named colour in a component. web/src/opscenter/tokens.css re-derives every token from the active theme's --color-* manifest, so a token repaints under all 42 themes and a literal does not. See color tokens.
  2. Every theme, every time. Before calling a UI change done, render it under the default and at least two more themes with visibly different accents and grounds (one light, such as codex). Use the picker at the top of this page to see the same thing for every component here.
  3. Every string comes from the one catalog. client/js/i18n/catalog.en.js, read in Svelte through t() from web/src/lib/i18n/index.svelte.ts and in legacy code through window.CloudeI18n.t. Copy is lowercase and plain. No em dashes, no en dashes, no emoji. A missing key renders the key itself, loudly.
  4. Words carry meaning, colour repeats it. A state is never colour only: a light has a label and a tooltip, a chip has text, idle and unknown differ by shape.
  5. Efficiency is god. No intro paragraphs above controls, no per-option explanations, no poller chatter, no hint text printed inside a menu (#558, #603). One line per thing. Long help folds shut.
  6. A new component, icon or pattern joins this guide in the same change. The drift test (tests/test_style_guide_drift.py) fails when a shipped class or Svelte component has no entry here, and when an entry here names something that no longer exists.

two trees, one look

client/js is hand-written vanilla JS served off disk; web/ is Svelte 5 + TypeScript + Tailwind compiled by vite into client/dist/app.js and app.css. The first question about any client change is which tree owns that screen today: read its mount path in the current source, not a dated inventory. Both trees read the same --oc-* tokens, because client/dist/app.css declares them on :root for every screen. The status light lives in both trees on purpose and is proven byte identical by StatusLed.parity.test.ts; change both or neither.

Tailwind ships utilities only, prefixed tw:, with no preflight. Use a utility for one-off layout inside a component; never use it to re-create a component that exists here.

where the older gold master references disagree, the shipped code wins

The gold master design references (docs/ui-switchover-design-references.md) came before the shipped Carnivore surfaces. Where they disagree, follow this guide:

  • Type. Gold master pairs IBM Plex Mono with PT Sans. Shipped Carnivore is one family: the platform monospace in --font-mono. web/src/opscenter/type.css declares JetBrains Mono faces for the measured dashboard mockup, but no shipped rule names that family, and --oc-font resolves to --font-mono today. Components write --font-mono, as every reference surface does (a family swap changes glyph advance, which is geometry).
  • Geometry. Gold master measures a 62px header and a 352px hero on a 100vw / 1672 unit. Shipped geometry is the fixed pixel set in tokens.css: 54px top bar, 31px widget header (the widget header), 26px rows, 12px gutter.

shared state classes

A handful of short class names in client/css/styles.css are state hooks the legacy screens toggle, not components: .active (the visible screen or the chosen item), .hidden and .visible, .danger, .error, .connected, .status, .is-on, .keyboard-active, .filter-hidden and .version. Reuse them only on the legacy elements that already carry them. In web/, state is a data-* attribute or a scoped class: directive, never one of these global names, because a global state class restyles every element in the app that happens to carry it.
