principles and the military terminal look

The canonical reference for how Carnivore looks. Every example is the real component in the stylesheets the app ships (the same list and order as client/index.html), in the theme picked at the top. Read this, then the section for the component you are touching, and copy what it shows.

the rules that bind every surface

  1. Military Terminal, everywhere. All UI, client/js and web/ alike, wears the Military Terminal look (Alex, 2026-09-25, docs/DECISIONS.md). That means: mono type (--font-mono), a title-row strip on its own ground with a hairline under it, small tracked uppercase labels, 1px hairlines between regions instead of cards and shadows (a column of several sections gets one bordered panel per section, a column of sections), small square corners (2px on controls), the accent used for ONE thing per surface, and focus drawn as the element's own border, a little brighter, same width (web/src/opscenter/focus.css).
  2. Copy, never invent. Using --oc-* tokens is necessary and not sufficient. PR #598 used only tokens and still shipped a rounded, accent-ringed field and a filled accent button; Alex rejected it ("looks the same. Not Military Terminal at all."). New UI copies the classes and patterns shown here. Where a scoped rule cannot be reached, restate it and name its source in a comment, the way client/css/text-prompt-modal.css does.
  3. Colour is --oc-* tokens only. Never a hex, rgb() or named colour in a component. web/src/opscenter/tokens.css re-derives every token from the active theme's --color-* manifest, so a token repaints under all 42 themes and a literal does not. See color tokens.
  4. Every theme, every time. Before calling a UI change done, render it under the default and at least two more themes with visibly different accents and grounds (one light, such as codex). Use the picker at the top of this page to see the same thing for every component here.
  5. New UI goes in web/ (Svelte 5), even on a legacy screen (Alex, 2026-09-12). A compiled component reaches the page only through mountPanel or ensurePanel (web/src/lib/mount.ts). Logic that renders nothing stays framework free in client/js.
  6. Every string comes from the one catalog. client/js/i18n/catalog.en.js, read in Svelte through t() from web/src/lib/i18n/index.svelte.ts and in legacy code through window.CloudeI18n.t. Copy is lowercase and plain. No em dashes, no en dashes, no emoji. A missing key renders the key itself, loudly.
  7. Every user action goes through an authenticated API route (Alex, 2026-09-25). A button is a client of a route, never a second implementation of one.
  8. Words carry meaning, colour repeats it. A state is never colour only: a light has a label and a tooltip, a chip has text, idle and unknown differ by shape.
  9. Efficiency is god. No intro paragraphs above controls, no per-option explanations, no poller chatter, no hint text printed inside a menu (#558, #603). One line per thing. Long help folds shut.
  10. A glance tells the sections apart. Where one section ends, where the next starts and what each one is must read without reading body text: each section its own title strip with the accent label, a hairline plus a real gap between sections, and one primary section, the one that holds the next step (Alex (example-owner), 2026-10-24, #2469 publish page mockup round 3: "I need better overall visual separation for intuitive. Quick understanding of different sections around here."; round 4 ruling 2, accepted the same day). The recipe: a column of sections.
  11. A new component, icon or pattern joins this guide in the same change. The drift test (tests/test_style_guide_drift.py) fails when a shipped class or Svelte component has no entry here, and when an entry here names something that no longer exists.

two trees, one look

client/js is hand-written vanilla JS served off disk; web/ is Svelte 5 + TypeScript + Tailwind compiled by vite into client/dist/app.js and app.css. The first question about any client change is which tree owns that screen today: read its mount path in the current source, not a dated inventory. Both trees read the same --oc-* tokens, because client/dist/app.css declares them on :root for every screen. The status light lives in both trees on purpose and is proven byte identical by StatusLed.parity.test.ts; change both or neither.

Tailwind ships utilities only, prefixed tw:, with no preflight. Use a utility for one-off layout inside a component; never use it to re-create a component that exists here.

where the older gold master references disagree, the shipped code wins

The gold master design references (docs/ui-switchover-design-references.md) came before the shipped Carnivore surfaces. Where they disagree, follow this guide:

  • Type. Gold master pairs IBM Plex Mono with PT Sans. Shipped Carnivore is one family: the platform monospace in --font-mono. web/src/opscenter/type.css declares JetBrains Mono faces for the measured dashboard mockup, but no shipped rule names that family, and --oc-font resolves to --font-mono today. Components write --font-mono, as every reference surface does (a family swap changes glyph advance, which is geometry).
  • Palette. Gold master's baseline is green on #010709 with green as the main action. Shipped Carnivore is a deep blue-green ground (#02161e, owner reference 2026-09-22) with a red accent (#ff4652), carried by the token still named --oc-orange.
  • Buttons. Gold master's primary is an outline. Shipped buttons copy the restart picker footer: a tinted interior with a 1px bright edge, no corner brackets (Alex, 2026-09-25, #637). See buttons.
  • Geometry. Gold master measures a 62px header and a 352px hero on a 100vw / 1672 unit. Shipped geometry is the fixed pixel set in tokens.css: 54px top bar, 31px widget header (the widget header), 26px rows, 12px gutter.
  • Navigation. Gold master draws a left rail on home. Alex had that rail removed on 2026-09-23; its rows live in the agents drawer's menu tab (web/src/opscenter/shell/rail-items.ts).

shared state classes

A handful of short class names in client/css/styles.css are state hooks the legacy screens toggle, not components: .active (the visible screen or the chosen item), .hidden and .visible, .danger, .error, .connected, .status, .is-on, .keyboard-active, .filter-hidden and .version. Reuse them only on the legacy elements that already carry them. In web/, state is a data-* attribute or a scoped class: directive, never one of these global names, because a global state class restyles every element in the app that happens to carry it.

how to read a component entry

A specimen, then a fact sheet, then the mistakes already made. A label that says live mounts the real component; markup copied from reproduces a legacy renderer's markup by hand in the shipped styles, and the drift test proves every class in it still exists.
