shared controls

One vocabulary of small controls for every screen (Joe (ccsliinc), 2026-09-29: "one uniform, layered, hierarchical CSS with standard controls across all screens"). They are app-level primitives, named for what they are and not for the page that first used them, and they live in one place, web/src/opscenter/controls.css, in the cascade layers primitives (the controls) and patterns (the group, the grids, the well), whose order is declared once, first, in client/css/layers.css. A screen reaches for these before it writes a control of its own. The settings page is the first screen built from them; its chosen mockup is docs/design/settings-appearance-options-2026-09-29.html, option 1.

the label column group

markupweb/src/opscenter/controls.css.oc-group

colors

the theme for the whole app. a session can still pin its own.

use
A page that holds several groups of related controls. A fixed side column names the group once, in the accent (.oc-group__label), with one line of hint (.oc-group__hint); the main column (.oc-group__main) holds the rows in an even grid, and a row that needs the width takes it with .oc-wide. A hairline closes each group. The group answers to the width of its PANE, not the window: put .oc-pane on the scrolling container that holds the groups, and the side sits above the main column until that pane is 820px wide, then goes to a 190px column beside it. Grids inside a group answer to the main column: .oc-grid-3 is stacked until it is 600px wide, .oc-grid-4 fills with cells of at least 140px. Hint text is --oc-fs-hint, never the inherited page size. A group whose main column is a wide grid (the notification routing matrix) adds .oc-group--stacked, which keeps the side above the main column at every pane width so the grid gets the whole pane.
one heading
The group is named exactly once. A page title above it, the group label and the row label are three levels; do not repeat the same word at each. A row alone in its group is named by the group.
spacing
One scale, 4 / 8 / 12 / 16 / 24 / 32 px, applied with gap and never with stacked margins. Colour is --oc-* tokens only.

check toggle

markupweb/src/opscenter/ui/Check.svelte.oc-check
use
An on or off choice: a member of a set (role="checkbox") or a single setting (role="switch"). A square box that fills in the confirm colour when on; the state is aria-checked. Never a native checkbox restyled, never a track and knob. An optional glyph (.oc-check__glyph) and a small right-hand note (.oc-check__note), and a hint: a quieter second line under the label (.oc-check__text over .oc-check__hint). With NO label text (the second row above, .oc-check--bare, set by Check.svelte when the label is empty) the frame around the box is not drawn, only the box; the border stays reserved but transparent so layout and the shared focus rule are unchanged. Give it an ariaLabel.
bare
.oc-check--bare (<Check bare ... />, second row above): no frame and no padding, for a check that sits inline in a row or a control strip that already has its own frame. Hover brightens the label and the box; keyboard focus is still the shared rule, which lights the transparent border. Worked examples: the Task Manager's row checks and its pop-out "hide completed" (Joe (ccsliinc), 2026-10-03: "need to remove outline on hide completed"). A check standing alone on a page keeps the frame.

segmented choice

markupweb/src/lib/item-settings/SettingsForm.svelte.oc-seg, .oc-seg__item
use
One choice from a SHORT list (up to four words), where every choice should show at once and cost one press: the settings overlay's enum fields draw it by default (lib/item-settings/schema-layout.ts::controlOf; a field may declare control: 'select' instead). One hairline frame, hairlines between items (never cards), small mono words; the chosen one takes the hover ground and bright text, and the state is aria-checked on a role="radio" inside a role="radiogroup", never colour alone. Focus is the shared focus rule. A longer list is a select (.oc-field).

scope filter (global, sessions, both)

markupweb/src/opscenter/ui/ScopeFilter.svelte.oc-seg, .oc-seg__item
use
The segmented choice above, fixed to three words, for any tab that splits machine wide work from a session's (Joe (ccsliinc), 2026-10-12, item 542: "sessions and global toggle for schedules and possibly other new tabs"). <ScopeFilter value onChange label /> is presentational; its model, ui/scope-filter.ts, owns the scopes, inScope(row, scope) and the per device memory (readScope / writeScope, one key per surface beside the remembered tabs). It sits at the end of a .oc-rc-bar strip on top of a run chart. Worked example: the developer widget's scheduled tab.

choice card

markupweb/src/opscenter/ui/Choice.svelte.oc-choice
use
One choice among a few, where showing the result helps: put a preview inside the card. Radio semantics (role="radio" in a role="radiogroup"). The one in use has a brighter edge, a filled dot and the word "in use" (.oc-choice__use). The preview inside is inert: no button of its own.

order list, buttons and well

markupweb/src/opscenter/ui/OrderList.svelte.oc-order, .oc-ibtn, .oc-btn, .oc-well
1context
25-hour window

a hairline well frames a preview.

use
A list where position matters: a number, the item (a check when the list also shows and hides), and a move-earlier and move-later pair (.oc-ibtn); an item that is off reads struck through (.oc-order__item--off). .oc-btn is the app's one button, mirrored declaration for declaration from the restart picker footer's .modal-btn family (Alex, 2026-09-25): quiet outline by default, .oc-btn--confirm the calm tinted confirm, .oc-btn--danger the dark red interior with a bright red outline, .oc-btn--alert the filled block for a rare alert only, .oc-btn--sm the compact size for a row of small actions, and .oc-btn--tool the quiet text control in a cell header (sort, view all, details). .oc-ibtn--bare is the quiet icon tool in a header (a cell's plus, the collapse chevron, the favourites star): no frame until it is pointed at, the glyph turns accent while its menu is open. .oc-ibtn--close rides on it for a close x (the widget header's): the destructive --oc-coral only under the pointer. .oc-ibtn--float is the faint floating icon (Joe, 2026-09-30): a 22px muted glyph at low opacity, placed out of flow over a surface by its caller, full on its own hover, on keyboard focus or while what it opened is open, and always full on a touch screen. The home pop-out glyph and an analytics card's details opener wear it. .oc-well frames a preview with a hairline. Small labels are .oc-sub, small notes .oc-key; sets of controls sit in .oc-grid-2, .oc-grid-3 or .oc-grid-4.
focus
Nothing here draws its own focus ring. Each control keeps a reserved 1px border and the one shared rule (web/src/opscenter/focus.css) brightens it.

common mistakes

  • A control restyled per page. A checkbox that looks different on two screens is a bug; add to controls.css or use what is there.
  • A native checkbox or radio in new code. Use Check.svelte and Choice.svelte.
  • Reordering with a drag only. An order list always has move-earlier and move-later buttons.
