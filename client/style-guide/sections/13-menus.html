menus and popups

Every floating menu is one look (.popup-focus) and, in compiled code, one driver (CascadeMenu.svelte). Menus hold actions only: no hint text, no decorative dividers, no explanations. The one addition is a LOCKED action: an item that needs a carnivore account while signed out keeps its place with a dim label, a star in --oc-yellow-bright and a small trailing "sign in" (.acm-locked in the cascade, .session-row-menu__item--locked in the row menu). It stays clickable, never aria-disabled: a click opens the sign in modal and then runs the action.

the cascade menu, and the "+" tab menu

liveweb/src/lib/drawer-tabs/CascadeMenu.sveltepress the dimmed "+" after the last tab, or a tab's icon
use
Every compiled popup menu: the agents drawer's add component, row detail and new session menus (#527), a terminal component's "+" tab menu, and the sort menu. <CascadeMenu root={nodes} anchor={button} label={t(...)} onClose={close} />. A node is {id, label} plus one of: children (a branch that opens a level), run (a leaf), checked (a radio item, the chosen one in the accent), agent (a session: its light and provider mark before the label, #554), sep (a rule above it), blocked (inert, with its reason). The account menu added four, inert for every other caller: a node's icon (an icons.ts name before the label, .acm-icon) and hint (its keyboard key in a <kbd class="acm-hint"> at the row's end, as the row menu's key), toggle with checked (an on/off menuitemcheckbox), and the props above (the top level opens OVER its button, for a button at the window's foot) and heading (a muted, unfocusable top line, .acm-heading, over a hairline). The search mode menu added a node's desc (a short muted note on the label's line, .acm-desc) and the prop wide (.acm-menu--wide, 220px minimum, 340px maximum), plus alignEnd, which right-aligns the menu to a control at the end of a field.
behaviour
Each open level is its own role="menu" panel fixed to the viewport, placed against the item that opened it. A branch opens on hover, click, ArrowRight, Enter or Space; ArrowLeft and Escape close one level; a pointer anywhere else closes all of them; focus returns to the anchor. A refused leaf may keep the menu open and say why in status.
hotkeys
Every item of every menu has a key by default (Alex, #1411), from ONE registry, web/src/lib/menu-keys/menu-keys.ts, so a verb keeps its letter in every menu: n new, r rename, c color, y copy, b load blueprint, a agent on/off, i set image, x remove image, g regenerate art, o company, v archive or restore, d delete. An item with no entry takes the first free letter of its label; one menu level never repeats a key; a refused item has none. The three primitives (CascadeMenu.svelte, the engine CellMenu.svelte, zone-shell/PlacementMenuHost.svelte (the one host of the bar key, section header, drawer card, glance tile, pop-out and tab menus; its settings form is .pmh-form), RailKeyMenu.svelte and GlanceMenu.svelte all draw through CascadeMenu.svelte since 2026-10-14 (the old panel component is retired), item-menu/ItemMenuHost.svelte, the one item menu every kebab, right-click and Shift+F10 opens) call assignMenuKeys and pressMenuKey; no menu handles keys itself. A key fires only from a keydown inside that open menu, never from a text field, and it CLICKS its item, so a destructive one still opens its confirm. The key is drawn by MenuKey.svelte, <kbd class="menu-key">: right-aligned, dim mono (--oc-text-dim, --font-mono), aria-hidden. The row menus take their letters from the same registry since wrapper package S-6 part 2.
"+" menu
Headings at the top level, sessions in submenus grouped by project, and it never lists a session already open as a tab in that component (Alex, #596, PR #600); a section with nothing left hides.

popup focus
Add popup-focus to the panel's class list and declare no border, ground or shadow of your own; the look is drawn once in client/css/popup-focus.css, which loads last so it wins at equal specificity. Worn by the row menu, the drawer group menu, the header kebab menu, the terminal tools and server controls menus, the session theme picker, the components popover, the add component menu, a panel's corner menu, a terminal cell's options menu, the background popover and the file drawer's options menu. Every centered dialog wears a scaled-up version of the same shimmer, reusing this file's compositor-only turn recipe through its own mg-sheen child and modal-glow-turn keyframes (popup-focus-turn stays declared only here) - see dialogs, "glow" and client/css/modal-glow.css.
row menu
The kebab on a session, browser, page, file or Layout row opens the ONE item menu (wrapper package S-6 part 2): the row types are entries in web/src/lib/item-menu/menus/row.ts (items in row-items.ts), drawn by item-menu/ItemMenuHost.svelte through CascadeMenu.svelte (a 14px icon, a label, the letter from the one registry), opened by item-menu/row-open.ts from the kebab, and from a right-click, a long press or Shift+F10 on the row (sidebar-shell/row-menu-gestures.ts). placeMenu puts its top-left at the kebab's bottom-left and flips and clamps it; a right-click hangs it at the pointer. An inert item shows its reason inline; "update and restart" and the Shift-held "restart now" wear the green update tone (.acm-item--update). The panel above is the retired legacy look, kept for reference.
a tab's menu, and a fold-out beside a menu (#1838)
A right click on a terminal tab (the Menu key or Shift+F10 on a focused tab) opens the row menu for that tab's session at the pointer, in that session's own theme and the global theme for a session with none (Themes.applyScopeTo on the panel and on the "add to" cascade host, handed back on close). The kebab's "actions" item opens the same panel as a FOLD-OUT beside the kebab menu, which stays open: hover, click or ArrowRight opens it, ArrowLeft or Escape retracts it (a second Escape closes the menu), and hovering a sibling item retracts it. A fold-out is placed by the app's one placement rule, placeMenu (window.CloudeWeb.placeMenu): right of the host, flipped to its left when there is no room, shifted up off the bottom edge and height-capped to scroll, so it never sits under or past the window's edge. No new class: it is the one item menu's CascadeMenu, which wears popup-focus.
a nested branch, from a flat panel (#954)
"add to" (a Layout row: "add"), and "send to", are branch items: since the row menu is the one item menu (S-6 part 2) they are ordinary CascadeMenu submenus, their levels built by addToNodes (web/src/lib/add-to-menu/host.ts) and computerNodes (web/src/lib/send-to/host.ts). Before that, the legacy panel opened them as a nested flyout via window.CloudeWeb.addToMenu. Hovering any other item in this panel retracts the flyout, the same as hovering a sibling retracts a submenu anywhere else. A leaf pick collapses the whole nested tree, this panel included; Escape or ArrowLeft on the flyout's own top level backs out of it alone. The chevron (.session-row-menu__chevron) is the same glyph as CascadeMenu.svelte's own .acm-chevron.
spacers between groups
Both kebab menus group their entries with a hairline (Task Manager item 262): open / navigate, identity (rename, pin, filing), info (show path, copy session id, crosstalk), schedule and notifications, lifecycle (restart, sleep or wake), and delete alone at the end; a group with no entry for a row draws nothing. The row menu (the one item menu) draws CascadeMenu's hairline, --oc-line-rule. A menu entry sets separatorBefore on the first entry of a group; the row menu derives it from the entry's order band (GROUP_STARTS in web/src/lib/item-menu/menus/row-items.ts).
component options
A tab's own icon opens CellMenu.svelte, the component options menu. It shows ONLY actions (Alex, #603): a disabled action's reason lives in that button's tooltip (data-tooltip), never as a printed line. It is not mounted on this page because its actions write the layout that syncs to every device.
overflow
At 620px of cell width a terminal cell's tool icons collapse into the session kebab menu, keeping every action in its session's context. When you add a bar icon, re-check that width: the keep-awake cup moved it from 600 to 640px.
themes
--oc-ground-card or --oc-ground-raised under the items, --oc-ground-hover on hover, --oc-strip-edge and --oc-focus-glow for the popup edge, black drop shadows (they must read on a light theme).
access
role="menu" with an aria-label naming what the actions act on, role="menuitem" buttons, arrow keys between items, Escape closes and returns focus to the trigger, the trigger carries aria-expanded. The legacy row menu trigger's focus outline is the accent; new triggers use cyan.

the anchored popup

liveweb/src/lib/dialog-frame/AnchoredPopup.sveltepress either control; Escape, a press outside or an answer closes it
use
Every popup that opens beside a control, or floats on its own without covering the page, is AnchoredPopup.svelte (wrapper package T-2); the centered modal is ModalShell.svelte (dialogs section). The popup brings only its body and its own class for size and layout; the frame adds .oc-anchored and popup-focus itself, so no popup declares its own edge, ground or shadow. The popup's rule for the frame is :global(...) in its own file, because the element is the component's. Worn by the widget info and settings popovers, the components list, the custom project color picker, the project tool window, the subagent and timer lists, the alert center, the duplicate and "no Task Manager" prompts, the account color picker and the terminal background popover.
a question
A destructive question that opens from the key that asked it (clear the board, end the session, delete the automation) is ConfirmPopup.svelte, the second specimen above: an alertdialog on this frame with a sentence, the quiet secondary cancel and the coral danger answer, both the base Button at the small size. Focus starts on cancel, Escape or a press outside answers no, focus goes back to the key. Never an inline strip with its own role="alertdialog".
placement
placement="below" (the default) puts it under the anchor, flips it above when the room below is short, clamps it to the window and makes it a full-width sheet at phone width, through web/src/lib/dropdown/placement.ts, the dropdowns' one rule. placement="manual" takes the popup's own geometry as style, computed in onPlace; the frame calls it on open, on a window resize, on any scroll and when its own size changes, so no popup wires those listeners again. topLayer promotes it with popover="manual" when an ancestor would clip it or contain it. Its defaults (position: fixed, z-index: var(--oc-z-popover)) sit in @layer base, so a popup's own rule wins.
behaviour
Escape closes it and stops there, so the page or strip under it never sees the same press (escape="window" hears it anywhere; escape="document" hears it in the capture phase without stopping it, for a popup holding a native picker). onEscape replaces the close for Escape alone (a picker that puts back the first choice). A press outside the popup and its anchor closes it (outside="capture" for one nested in a menu, "none" for a form). dismissable (a value or a check) holds both while, for example, a modal the popup opened is up. Every other key reaches the popup's own onkeydown.
access
role="dialog", or "alertdialog" for a question, named by label. Focus goes to the first control on open (or initialFocus: a selector, self or none) and back to the anchor on close when it was inside. A showing role="dialog" is the floating layer that owns Escape (web/src/lib/sidebar-widgets/escape-guards.ts). The dialog-frame scan (web/src/lib/zone-shell/host-scan.ts) refuses a role="dialog", role="alertdialog" or aria-modal on a plain element anywhere but the two frames.

the tooltip

liveweb/src/lib/tooltip/tooltip.tstooltip.cssrest the pointer on an icon, or tab to it
pin to top
use
A TOOLTIP ONLY SAYS WHAT AN ICON-ONLY CONTROL DOES (Alex (example-owner), 2026-10-01, #1209: "only leave tool tips when describing what an icon does"; narrowed the same day: "you still have tooltips on items names here"). It goes on an icon-only button or toggle and on an (i) mark whose job is to explain. An item's name never gets one authored on it, and neither does a heading, group header, section title, label, row, chip, meter, or a button or link that already shows text. tests/python/design_system/test_tooltips_icon_only.py fails when a heading, name or label element carries one. Where a removed tooltip was the only accessible name, keep an aria-label.
CUT-OFF TEXT REVEALS ITS WORDS, AND THAT IS NOT A TOOLTIP (Joe (ccsliinc), 2026-10-14: "all cutoff text with ..., thats not a tool tip its reading the damn words. and tool tips and info are 2 things."). Any text the screen cuts short with an ellipsis or a line clamp, in either frontend tree, shows its full words on hover after the shared delay, and only while it is actually cut off; a name that fits shows nothing. You write nothing for it: revealCutOffText in web/src/lib/tooltip/cut-off-reveal.ts runs from the one controller and sets data-tooltip from script, so the ratchet above (no authored tooltip on a name) still holds. An element that authors its own tip keeps it; truncatedTip remains for a site whose full text differs from its visible text. cut-off-reveal.test.ts and row-name-title.test.ts hold it.
IT MUST TELL THE READER SOMETHING THE SCREEN DOES NOT (Alex (example-owner), 2026-10-12, #1686: "remove all the dumb shit ones that just state the fucking obvious"): a keyboard shortcut, why a control is off, a unit or time window, what a click will do to your data, or the only name of a glyph nobody could guess. The plain name of a self-evident icon (house, gear, X, magnifier, trash, arrows, a pencil, a plus, any drawer tab) is NOT such a thing: keep it as aria-label and draw no tip. tooltipTargetFor in web/src/lib/tooltip/tooltip.ts also drops, on its own, a tip whose words (less one leading open, close, show, hide, fold, unfold, toggle, go to or pop out) are already in the control's visible text and that is not clipped; web/src/lib/tooltip/tooltip-obvious.test.ts holds it.
The app has ONE tooltip (Alex (example-owner), 2026-09-27, #981): shown only after the pointer or keyboard focus rests 750ms (SHOW_DELAY_MS, the one setting for every tooltip), one look, never two at once. Give a control its words with title or data-tooltip (never both) and keep aria-label for its name. Nothing to wire: installSharedTooltip() runs once at boot and serves client/js and web/ alike.
look
It reads as a tooltip, not a menu (Alex (example-owner), 2026-10-01: "it shouldn't look like a menu. it should look like a tooltip."): small mono text on a quiet raised ground (--oc-ground-raised), a neutral hairline (--oc-line-frame), a 2px corner, no accent edge, no glow, no shadow, and a small pointer toward its target. It does not wear .popup-focus, which belongs to menus and popups. It takes no pointer events.
behaviour
One .cc-tooltip box on <body>, in the look above. While the pointer is inside an element its title (and every ancestor's) waits in data-tooltip-title, so the browser's own tooltip never fires beside it; it comes back on leave. data-tooltip-side (top, bottom, left, right; default top) is a preference that flips when it does not fit. A press or Escape hides it until the pointer leaves; a touch never shows it.
cut-off text
Text clipped with an ellipsis (a Task Manager row's title) may show its complete text in this same box: the truncatedTip action (web/src/lib/tooltip/truncated-tip.ts) sets data-tooltip on hover only when the line is measurably clipped (Joe (ccsliinc), 2026-10-10), so a line that fits shows nothing.
none
A kebab carries no tooltip: its icon speaks for itself. data-tooltip-off on a region silences it (the header's folded menu, whose rows print their labels); an empty value on the nearest carrier means none; a control whose popup is open (aria-expanded="true") shows none.
access
The shown box is role="tooltip" and the target's aria-describedby names it while it is up. Keyboard focus shows it after the same delay; a mouse click's focus does not.

a widget's menus: the one widget menu

A widget draws no menu of its own (docs/widget-spec.md section 11, Joe (ccsliinc), 2026-10-19). The host draws the one widget menu; the widget declares its controls into it with declareWidgetActions and hands the controls themselves up into the host header. The menu opens from the widget's icon on the rail and the icon at the top left of its title strip, on a click, a right-click or Shift+F10; both icons are the host's, so a widget wires nothing for them. A widget's rows get no menu of their own (Joe (ccsliinc), 2026-10-19, item 1030 message 5597: "not every line. just the icon on rail and icon on top left"). Menu items take their letters from the one registry. The Widget Lab's starter cell is a working copy.

common mistakes

Agent chat menu (issue #2613). The agent chat's title strip (ChatBar.svelte) draws no menu button and no dropdown of its own (#2567): it declares its rows to the one item menu, and the strip takes a right click (menuRightClick) and Shift+F10 (forwardMenuKey) into the menu (in a widget frame the rows are also declared to the widget's one menu). A Task Manager row does the same (task-manager-row-menu.ts). rename agent asks through the one text prompt; turn off asks in a fold-out row (a leader types its name in the modal).

  • Hint text inside a menu. "there is no row below this one" printed in the options menu was removed (#603). A disabled item is grayed and its reason is its tooltip (Alex (example-owner), 2026-10-21, #2071): every menu (CascadeMenu blocked, the row menu, the widgets place menu) draws the item dim with aria-disabled (it keeps focus and hover), data-tooltip carries the reason, and no reason line is printed. A tap on a disabled item on a touch screen shows the tip and runs nothing.
  • Decorative divider lines. The border above the old menu note line was removed with the note (#603). A sep separates groups of actions, nothing more.
  • A second menu component. Reuse CascadeMenu; #527 added radio items to it rather than forking.
  • A widget's own options kebab. The files redesign draft drew a three-dot button in its body that opened a private CascadeMenu (collapse all, refresh, show dot files): a second widget menu beside the host's one (2026-10-19). Its items belong in the one widget menu through declareWidgetActions; only the terminal keeps a kebab. menu-conformance.test.ts and the gate fail it.
  • A session entry without its light and mark. Pass agent facts; the order is light, mark, name.
  • A literal label. Several row menu labels are still literals in web/src/lib/item-menu/menus/row-items.ts; a new item takes a catalog key (session.menu.*).
  • A CSS tooltip. An ::after bubble reading attr(title) showed instantly and the native one followed it, two looks at once (#981). Set title or data-tooltip on an icon-only control; the one tooltip does the rest.
  • A tooltip on a heading, label or text button. "expand the terminals group (9 agents)" over a drawer heading looked like a menu and said what the text already says (#1209). Only an icon whose glyph is not self-evident or an (i) mark carries one, and a name cut off by an ellipsis gets none (an item's name never does); give the heading an aria-label if it needs a spoken name.
  • A tooltip that states the obvious. A title or data-tooltip on anything that repeats its visible text, names a self-evident icon (house, gear, X, magnifier, trash, arrows, any drawer tab), or glues open, close, show or fold onto a name already on screen ("open SysOp" on a node labeled SysOp, "swarm" on the Swarm tab, "close" on an X) (#1686). Say something the screen does not, or say nothing.
  • A menu the drawer repaint destroys. The legacy drawer rebuilds its rows from an HTML string on every poll; anything mounted into it must adopt and move its nodes, not be recreated.
