do and do not

The rules this repo learned the expensive way, each with where it was learned. Read the list before a UI change and again before calling it done.

look

do

  • Copy a reference surface's classes and patterns (#597, PR #605).
  • Choose from a list with the picker (ModelPicker): grouped, a service logo before each label. It is the default dropdown.
  • Use --oc-* tokens for every colour; derive with color-mix() when none fits.
  • Show selection and hover as the --oc-orange-tint ground (#431, PR #459).
  • Divide list items with grey --oc-line-faint hairlines, and prefer more space to less.
  • Copy one of the three meters (segmented, limit gauge, bottom bar) for any meter (#637).
  • Keep the accent for ONE thing per surface.
  • Draw every icon in a tab at 14x14; the Shift skull alone at 16 (#569, #606).
  • Put per-row actions right-justified on the same line as the title (#151).
  • Put secondary info to the right of the primary label, dimmed, middle-dot separated; truncate the primary first (PR #548).
  • Make toggle icons grey when off and coloured with a small living detail when on (#151, PR #560).
  • Cap and centre content at wide widths; stack at 1023px.

do not

  • Hardcode a hex, rgb or named colour in a component.
  • Mark selection with a red outline (#431: "that looks horrible").
  • Use accent-coloured dividers.
  • Ship a filled accent or red block for an ordinary act (#592, #598, #637); the filled .modal-btn-alert is for a rare alert only.
  • Redraw, recolour or stretch the brand art (brand).
  • Mix icon sizes in one row, or draw a second robot, kebab or provider mark (#569).
  • Add decorative divider lines to a dropdown menu.
  • Stretch content edge to edge at 2560px, or scroll sideways at 390px.
  • Use a pill-shaped radius or a hover lift, scale or glow on a button.
  • Mark two sections as primary, or make every strip equally loud.

words

do

  • Take every string from client/js/i18n/catalog.en.js; lowercase and plain.
  • Say a state in words and only repeat it in colour or shape (idle and unknown differ by shape).
  • One header line, one line per option, a tag only where the outcome differs (#558, PR #571).
  • Fold long explanations shut by default (#535).
  • On a settings surface, say in plain words what a feature does, not how it works, beside one large switch.
  • Name the act on a button: "kill and restart", "uninstall".
  • Tell sleep from kill: sleep keeps the row in place with a moon, kill files it under recently closed (PR #538).

do not

  • Print hint or explanatory text inside a menu (#603); a disabled reason goes in the title.
  • Write intro paragraphs above controls, or per-option explanations (#558).
  • Narrate: recommendations and poller chatter came out of the providers panel.
  • Put a countdown in a drawer box; it lives on the full page (PR #548).
  • Use em dashes, en dashes or emoji anywhere, the catalog included.
  • Print absent as zero, or unknown as idle.
  • Say "ok" or "yes" on a button.

build

do

  • Build new UI in web/ (Svelte 5), mounted through mountPanel or ensurePanel.
  • Back every action with an authenticated API route first.
  • Reuse CascadeMenu for every menu (#527), ModalShell for every compiled dialog, SessionFace wherever a session appears (#554).
  • Read row fields at the right level of SessionInfo (gotcha 1).
  • Await the newest list load before resolving a deep link (#543, PR #561).
  • Make anything mounted into the legacy drawer survive its repaint.
  • Give an icon-only control a tooltip with title or data-tooltip, never a CSS bubble; the one tooltip delays it and keeps it inside the viewport (#981). A tooltip only says what an icon-only control does: none on a name (cut off or not), heading, label, row, chip, meter or text button (#1209).
  • Round reset times to the nearest minute (resetParts) and compact token counts (compactContextTokens).
  • Re-check the terminal bar's fold width when adding an icon (600 became 640 for the cup).
  • Change a status light in BOTH trees (StatusLed.parity.test.ts).
  • Change a theme colour everywhere it is spelled (theme.json, macOS/main.js, tokens.css fallbacks).
  • Add a new component or class to this guide and its registry in the same change.

do not

  • Fork a menu, a dialog frame or a status light.
  • Invent a second bucket for a concept that already has a home (#512).
  • Put search in the header (#428, PR #461).
  • "Fix" a grey status flash in the client: it is the watcher under load (#524).
  • Recolour a token and assume the visible box changed; grep the served app.css for the selector that paints it (a1459054).
  • Key anything on a tmux name; key on the session uuid (gotcha 4b).
  • Let a chrome element vote on, or resize, the terminal pane.
  • Wait on a bare requestAnimationFrame for work a hidden tab must do (gotcha 9).
  • Stage client/dist on a branch; it is built once at merge (#556).

verify

do

  • Render under the default and two more themes with different accents, one of them light, before calling it done.
  • Screenshot the surface beside the ledger or the catalog.
  • Assert concrete computed properties (an outline, a 2px corner, a cyan focus) in a browser test, not "uses tokens" (tests/test_text_prompt_modal_military.py).
  • Prove a check can go red before trusting it green (gotcha 11).
  • Scope "no console errors" to errors from the component you changed; a throwaway server logs its own noise.

do not

  • Trust a render at the default theme alone: it cannot tell a token from a literal.
  • Treat a skipped or could-not-run check as a pass (exit 2 means could not determine).
  • Run npm ci through a symlinked web/node_modules; it empties the shared install.
