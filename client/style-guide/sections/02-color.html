color tokens

Every colour in Carnivore is an --oc-* token. web/src/opscenter/tokens.css is the only file allowed to hold a colour literal, and it re-derives every token from the active theme's --color-* manifest at :root, [data-session-theme]. The table below reads the live values: switch the theme at the top and every swatch, value and contrast figure repaints, which is exactly what a component using these tokens does.

how a token reaches a component

  1. A theme's client/css/themes/<id>/theme.json lists cssVars: about fifty --color-* values plus --font-mono and the --radius-* set.
  2. Themes.applyTheme(id) (client/js/themes/registry.js) writes them onto :root through ThemeVarWriter and sets <html data-theme>. The home page calls it through applyGlobal, which also saves the choice; this guide calls it bare so it saves nothing.
  3. tokens.css maps them onto the --oc-* vocabulary. A session pinned to its own theme gets the same mapping on its own subtree through [data-session-theme], so two terminals in two themes sit side by side on one page while the chrome stays on the global theme (issue #318).
  4. A component reads only --oc-* (or a local alias of one, such as the ledger's --pl-* and the catalog's --cat-*, which are declared once at the screen root from --oc-*).

what the accent is for

The signal colours carry the same meaning everywhere: --oc-green working or ok, --oc-yellow waiting on you, --oc-cyan notice, --oc-coral danger or failure. A theme may move their hues but never their meanings, and each always travels with a word.

what a theme must define

A theme that leaves one of these out falls back to the Carnivore literal behind it in tokens.css, which reads as a stray Carnivore colour in someone else's palette. Define all of them:

--color-header-bg --color-bg-page --color-bg --color-bg-elevated --color-bg-card --color-bg-hover --color-bg-overlay --color-border --color-border-subtle --color-fg --color-fg-muted --color-fg-subtle --color-fg-faint --color-accent --color-accent-strong --color-accent-bg --color-success --color-info --color-warning --color-danger --font-mono.

Legacy stylesheets still read a few --color-* names directly (for example --color-danger in .modal-btn-danger) and the --radius-sm, --radius-md, --radius-lg, --radius-pill and --radius-full set. Three themes zero every radius, so no design may rely on a rounded corner to carry meaning. The ground colour of the default theme is spelled in three places that move together: client/css/themes/carnivore/theme.json, macOS/main.js (the window background, which only takes effect after an app restart) and the fallbacks in tokens.css (docs/theme-catalog-layout.md).

the literals that exist today

A handful of shipped rules still hold a literal. They are recorded here so nobody copies them as precedent:

  • The provider marks: claude's starburst carries its brand orange as a literal (client/js/agent-family-icon.js), because a brand mark is not a theme colour.

common mistakes

  • A hex in a component. It looks right in Carnivore and wrong in 39 other themes. Use the token; if no token fits, derive one with color-mix() from two that exist, the way --cat-failure-wash does, and name why in a comment.
  • Recolouring a token nobody sees. Commit a1459054 changed the cell frame border and nothing on screen moved, because the visible boxes (.oc-tile) draw their own edges. Grep the served app.css for the selector that paints the pixel before calling a colour change done.
  • Accent as a frame. An accent border around a panel, an accent divider, two accent buttons side by side. The accent marks one thing.
  • Reading --color-* in new code. Those follow the manifest's raw names and skip the derivations (the dim, tint and mix steps); new code reads --oc-*.
  • A fixed colour for a scrollbar or a glow. A fixed red is wrong on matrix, on the four-colour gameboy LCD and on codex, whose ground is near white. Derive from the theme's own accent and ground, as --oc-scrollbar-thumb does.
