swarm page

The Swarm page is a main-area menu page (id huddle-swarm, fragment #swarm, plugin page key huddle.swarm, opened from the "swarm page" link on the drawer panel's bar, keepDrawerTab so the drawer stays on the Task Manager tab). It wears the shared page frame (web/src/opscenter/ui/Page.svelte and Tabs.svelte) with four tabs: ledger (the default), org chart, nodes and board; its settings are not a tab: they live in the swarm plugin's settings pane on the plugins page (see settings below). The three agent views draw the SAME floor as the drawer panel (swarm/floor.ts, never a second population rule), arranged as a tree by swarm/swarm-tree.ts; the quiet "show inactive (N)" link and its per-device key are the panel's.

the ledger, the org chart and the settings

liveSwarmLedger.sveltethe ledger, then the org chart (wheel or the plus and minus keys to zoom, drag to pan), then the settings form (shown here, but it lives on the plugins page, not on the Swarm page)
ledger
<SwarmLedger tree agents now swarm asking onOpen />: the hierarchy as collapsible rows (.pkg-row, a hairline under each) under a header row of tracked labels (.pkg-head). Every row and the header share ONE column grid (.pkg-cols), so kind, status and the rest start at one x at every depth: depth indents only the first cell (.pkg-who, with the caret). A collapse caret (.pkg-caret), a 28px character, the name, the rank in tracked capitals (.pkg-rank), the state in words, the job, the effort and the open alert rung (.pkg-alert). A vacant seat is a row with a dashed square (.pkg-seat) and no character. A click opens the row's target; a seat's click turns its agent on at once (the server runs git init in a folder that is not a repo, #1434), and only a refusal draws a line under the view (SwarmSeatRefusal, .pkg-refusal, the route's reason in the warning token).
org chart
<SwarmOrg tree agents now swarm asking onOpen />: a top-down tree in a 1px frame (.pko), links drawn as SVG paths (.pko-link), nodes are characters with their names (.pko-node). It grows down, not sideways: SysOp, companies and projects sit side by side, while leaf agents (no children) stack under their parent as rows, face left and name right (.pko-node--leaf), each hung off a trunk by a left-side elbow; more than six wrap into two columns, more than twelve into three. A node with both leaves and children (SysOp with its own agents) hangs its stack right under it, and its children's row sits below the stack. A cut name shows whole in the tooltip. The layout and the zoom are pure (swarm/org-layout.ts): one link per non-root node, zoom held between 0.4 and 2.5, and fit never shrinks the chart below its own size. A row of siblings (companies, projects) wider than the frame wraps onto a new row below, still under the same parent and reached by one connector bus, recursively; only a single column wider than the frame pans. Every view on the page draws the selected node's lineage (lineageFloor: the node, its ancestors up to SysOp and its descendants). On the nodes and org chart tabs a plain click (or Enter) opens the node's terminal, a vacant seat still asks; a shift+click (or Shift+Enter) toggles the filter onto that node, and the filtered node wears the focus border (aria-current, the same brightened hairline as focus.css). The controls (.pko-ctl, .pko-key) are the drawer bar's key frame.
nodes
<SwarmPanel flow ... density="expanded" />: the drawer panel at page width. SysOp gets its own SYSOP label and every section is fixed-width cells from the left edge, so nodes share one x and one gap at any width.
settings
<SwarmSettingsForm />, drawn on the ONE Swarm settings home, the swarm plugin's side pane on the plugins page (HuddleSwarmSettings.svelte, under the manifest fields; deep link #plugins/huddle/settings); the Swarm page has no settings tab and no second copy. Rows (.pkg-set-row, text left, a .oc-field select or number right): the default view, the default density, the character set (follow the theme or a named swarm), the upper ranks' permission posture and the close-out window in minutes (1 to 1440). Each change is one PUT /swarm/settings, one value for every device; a device's own choice (its remembered tab, its density keys) wins. Under them the look section (.pkg-look, a .pkg-look-title heading in small tracked capitals with a hairline under it): the agent colors (by project or random), a body shape per agent type (SysOp, company, project, agent: square, circle, hexagon, triangle, diamond, pentagon, octagon, star, shield or cloud) and an animation per status (any status's movement, or still), each row with a live Character in a .pkg-look-figure on its left; .pkg-look-note is the hint above the animation rows. Reduced motion and a hidden tab still freeze every character (docs/swarm.md 13.9).
never
No second population rule and no second swarm reader: the page and the drawer panel both call activePack in swarm/swarm-settings.svelte.ts. A device's choice is never overwritten by a default.

the board

The board tab is the Swarm task board (web/src/lib/swarm-board/, docs/swarm-board.md): every card the swarm holds, in five views behind one switcher. Swimlanes is the default; list, timeline, calendar and columns by project are built too. Checked under carnivore, dracula and carnivore-light. The page body is the board's one scroller (.pkg-body--scroll, on the board tab only): the page frame is a fixed, overflow-hidden column, so the body takes the height under the tabs and scrolls, and every view's sticky rows ride on it (#1432).

The search (.sbb-search, the shared SearchField) sits right and takes a full row below 720px. Loading, off and error lines are .sbb-note (.sbb-note--bad in coral).

A placeholder is <ViewPlaceholder view data /> (.sbp, a tracked label .sbp-label and one line .sbp-text).

card actions
<CardActions card data bind:mode only? /> (.sba): the keys a card's stage offers (stageActions in card-actions.svelte.ts), each a 24px square icon key (.oc-ibtn--bare with .sba-key, quiet until hovered, its tooltip and spoken label from the catalog): top and bottom (to-top, to-bottom) on a waiting card, pause on in progress, mark done (check) on review, the auto-promote toggle (arrow-up-circle, aria-pressed, green while on, .sba-key--on) on todo, then reclassify (cycle), archive, collapse (shrink / expand) and delete (trash, coral on hover, .sba-key--danger) on every card. Each calls its owner route at once, except reclassify and delete, which open <CardActionPanel> in the card (.sbp, a hairline above it): reclassify is a column dropdown and a note (.sbp-label, .sbp-field) with cancel and an outlined move (.oc-btn--confirm); delete asks first (.sbp-ask) with cancel and delete in .oc-btn--danger (.sbp-keys). Reuse these two in any view that draws a card.

never
No second card reader and no timer at idle: every view reads the one createBoardData (board-data.svelte.ts), which re-reads on the pushed cplug.huddle.cards family and polls only while that family is not pushed. No hex in a view: color is --oc-* only.
