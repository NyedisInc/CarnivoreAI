pills, badges and chips

Short evidence beside a name: a host, a wrapper, a state, a count. Small, square-cornered, one word or two, and never the only place something important is said.

status pill

liveweb/src/opscenter/ui/StatusPill.svelteAgentTier.svelte
use
A state word with a coloured dot in a compiled table or card: <StatusPill label={t(...)} tone="var(--oc-green)" dot />. Props: label (required, from the catalog), tone (a var(--oc-*) string, default green), showLabel (default true), dot, shape ('solid' or 'hollow'; hollow is "not measured", the same shape rule the status light uses). AgentTier is the robot mark plus an agent name.
not for
A session's status in a row: that is the status light (status light), which carries both rings and every signal. A pill is for states that are not a session's attention state.
access
With showLabel={false} the label still reaches the accessible name; do not drop the label prop.

chips and counts

state chip
A card's credential state is a chip that says the state in words first and repeats it in colour (the base Tag with tone ok, warn, danger or neutral in LedgerCards.svelte; live in the ledger): tracked capitals in the signal colour on a softened edge. An unmeasured state is the neutral tag.
command chips
The slash command favourites are chips (.command-chip, FavoriteChips.svelte, client/css/slash-command-chips.css): a tap target that inserts a command, reorderable by drag with a grip. The grip ([data-fav-grip], a full-height strip) and the unstar key ([data-fav-star], a 44px square at every width) are the base quiet IconButton. Two per row under 600px.
counts
A count is plain text in the secondary tier beside its label (ledger-total__count), or the toast's ×3 badge. Absent is not zero: print nothing, or "unknown", never a fabricated 0.

subagent count

markup copied fromweb/src/lib/sidebar-shell/row-chips.tsstyles liveclient/css/subagent-count.css
3 sub 2 2
use
How many subagents a session is running right now (issues #747, #748). The chip sits BESIDE the status light, never on it: the light's rings keep their meaning. <SubagentBadge running={row.subagents_running} total={row.subagents_total} sessionId={row.session.id} name={...} /> in compiled code (SubagentBadge.svelte); subagentChip(r) in the drawer row (web/src/lib/sidebar-shell/row-chips.ts). Both wear .subagent-count. A click opens the read-only list (SubagentList.svelte, see menus).
rollup
.subagent-count--rollup is the summed, non-interactive form on a group or project heading and in the running sessions header; <SubagentBadge rollup rollupTitle={...} />. A session drawn twice in one band is counted once.
density (drawer row only, issue #848)
The drawer row shows the count only ONE way at a time, gated by web/src/lib/drawer/density.ts's mode: cozy draws the clickable .subagent-count chip beside the status light; detailed draws a bare number instead, .session-row__subagent-count, beside the agent icon (SessionModelIcon) rather than beside the light, with no border and no click target (subagentCount(r)); compact and every other density draw neither. The project/group heading rollup above is a separate call site and is NOT density-gated - it draws at every density.
workflow (issue #852)
While a Workflow run is in flight the bare count turns blue: one modifier, .session-row__subagent-count--workflow, overriding color alone with --oc-cyan, and the title gains "running a workflow". It reads workflow_active off the listing WRAPPER, projected from the same watcher observation as the counts; only a measured true turns it, a null (not measured, or codex, which has no Workflow tool) keeps the green.
null is not zero
Nothing draws for a null, absent or zero count: subagents_running is null when the watcher has not measured the session and for codex (subagents_state not_applicable). Read it off the WRAPPER, never info.session.
themes
The working hue, --oc-green, with a 45% edge on the chip; the bare inline count uses the same token with no edge and no background.

timer chip

markup copied fromweb/src/lib/sidebar-shell/row-chips.tsstyles liveclient/css/timer-chip.css
use
How soon a session's next LIVE in-session timer fires (issue #893): a ScheduleWakeup or a CronCreate job whose claude process is alive and set it. It reads the time to the next fire ("18m", "3h", "2d", "due"), or the live count when no fire time is known. It sits beside the subagent chip, never on the light, and feeds neither the light nor the idle clock. <TimerBadge live={row.timers_live} nextFireAt={row.timers_next_fire_at} sessionId={row.session.id} name={...} /> in compiled code; timerPlan(r) in the drawer row (web/src/lib/sidebar-shell/row-chips.ts), which asks the same timerChip helper for its words so the two places say the same thing. A click opens the read-only list (TimerList.svelte, see menus).
density (drawer row)
Drawn in cozy and detailed, never compact. It is a different fact from the subagent count, so detailed draws both.
null is not zero
Nothing draws for a null, absent or zero timers_live: null means not measured, and codex rows are timers_state not_applicable. Read it off the WRAPPER.
themes
Calm by default: --oc-text-secondary with a 45% edge, because a timer is a fact about the future, not work and not a question. Hover lifts to --oc-ground-hover; focus is the shared brightened edge (focus.css).

common mistakes

  • Colour-only status. A green dot with no word. Every chip carries its word.
  • A pill for prose. A badge holds a word or two; a sentence goes in a tooltip or a line.
  • A pill-shaped radius. Chips use 2px to --radius-sm corners, not 999px.
