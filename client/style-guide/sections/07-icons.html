icons and marks

Every icon is inline SVG compiled or scripted into the page: nothing is fetched, so no img-src relaxation and no icon can fail to arrive. Every stroke is currentColor, so the surrounding text colour, and therefore the theme, colours it.

sizes
14px inside a tab: the component icon, the provider mark, the close "x" and the "+" all render 14x14 so nothing in the row reads bigger than its neighbour (Alex, #514 and #569; a 20x20 session-type icon tried at 8c5cff33 was replaced by 14x14 in #569 the same day). The Shift-held skull is the one ruled exception at 16x16 (Alex, 2026-09-25, issue #606, PR #607); the 2px comes out of the tab's padding, never its height. 16px in chrome and menus. 20px for the header kebab and the few larger marks.
lock
lock (#1200): a padlock, the account menu's "lock this device" row (the computer's TOTP lock, separate from the carnivore account's sign out, which keeps log-out).
colour
Inherit it. Set color on the button, never fill or stroke on the icon. A muted icon is --oc-text-secondary; hover lifts it to --oc-text-primary or --oc-text-bright; a destructive icon (the skull) is --oc-coral.
access
The svg is aria-hidden. An icon-only button carries its own aria-label and a title; an icon beside a label adds nothing.
unknown name
Falls back to the neutral grid glyph rather than an empty box. If you see a grid where you expected your icon, the name is misspelled.

the global widget mark

use
A widget that has a local variant (one session) and a global variant (every session) marks the GLOBAL one with a small globe in the lower right corner of its icon (web/src/opscenter/ui/WidgetIcon.svelte, .oc-wicon around the glyph, .oc-wicon-globe the mark; Joe (ccsliinc), 2026-10-10). Draw a widget's icon with <WidgetIcon name={manifest.icon} widget={manifest.id} size={15} /> instead of Icon; every surface that shows a widget icon already does.
look
The mark is the globe entry of the compiled set at 0.6 of the icon (never under 8px), in the icon's own colour on a --oc-ground-panel disc, so it follows every theme. The local variant is drawn bare.
adding a global sibling
Add its cell id to GLOBAL_WIDGET_IDS in web/src/opscenter/widgets/global-scope.ts; no other file changes.

the shared 16px glyphs

liveweb/src/lib/Glyph.svelteevery record in client/js/icons/glyphs.js

These glyphs are DATA, not markup: one set of coordinates in client/js/icons/glyphs.js, drawn by two renderers (glyphSvg(name, size) for the legacy tree's innerHTML, <Glyph name="..." /> for Svelte). Add a glyph by adding its records there, never by pasting an SVG string into a component. They are 16x16 on a 0 0 16 16 box, currentColor. A glyph may reuse another set's geometry through a transform attribute on its records (wolf, the Pack icon, is the opscenter 24 box outline scaled by 0.6667; both renderers pass transform through, so ONE outline draws the Pack everywhere). The row menu's own icons (client/js/session-row-menu-icons.js) borrow from this table for the same reason.

the icon picker and picked icons

liveweb/src/lib/icon-picker/IconPicker.svelteinside a green parent, a heading drawn by IconMark above it
liveweb/src/lib/icon-picker/IconPicker.sveltethe same picker in a violet parent, nothing chosen
use
The ONE way a user picks an icon for something they named: a group, a wrapper group, a widget, a user tab (issue #764). <IconPicker value={icon} onChange={(id) => save(id)} />, with optional onCancel (Escape) and autofocus. It never saves: the caller writes the id through its own documented route. Never build a second picker. Contract: docs/icon-picker.md.
render
Show a picked icon with <IconMark id={icon} size={12} /> in Svelte, or CloudeGlyphs.iconSvg(id, 12) in the legacy tree. Never map an id to a Glyph name by hand. An empty or unknown id draws nothing at all, so a row with no icon lays out exactly as it did before.
stored value
The icon's id string from client/js/icons/icon-registry.js, or null for none, inside the one JSON shape (#727). Ids are forever: never rename or remove one; retire it through RETIRED_ICON_IDS.
colour
INHERITED FROM THE PARENT, never chosen (Joe, 2026-09-26). The picker has no colour control, its grid sets no color, and the selected cell's ring is currentColor, so the choices preview in the colour of whatever the picker sits in.
keyboard
The grid is one tab stop (listbox): arrows move a cell or a row of eight, Home and End jump, Enter or Space chooses, Escape calls onCancel. ArrowDown in the search field enters the grid. "No icon" is always the first cell.
adding an icon
Draw it in client/js/icons/glyphs.js on the 16 box, then add one entry to icon-registry.js and its icon.* name to the catalog. Action glyphs (trash, close, pencil, restart) are never pickable: a group wearing a trash can reads as an instruction.

Mapping an icon id to a glyph by hand, or falling back to nothing: an unknown id falls back to the family mark, which is what the wrapper wore before an icon was chosen.

The size master toggle (issue #998, Alex (example-owner), 2026-09-27: "a gold crown icon. lit for master"): SizeMasterCrown.svelte, the .size-crown button in a terminal's toolbar, just left of the kebab (folded into the kebab as a menu item below 340px of cell width). The crown glyph (client/js/icons/glyphs.js, also pickable in the IconPicker) is drawn three ways from data-size-master: master is lit, filled in --oc-yellow-bright (the theme's own warning gold); watcher is a dim --oc-yellow outline (another window sets the size); none is a --oc-text-dim outline (smallest window wins). Colour only from those tokens, never a literal gold; the label says which state, from the catalog (terminal.size_master.*). Size only: it never gates typing.

Two more doors onto the same claim (issue #1019, Alex (example-owner), 2026-09-27), no second mechanism: below 1024, where the toolbar and its crown do not exist, #headerSizeMasterBtn (built by client/js/header-menu.js's _buildSizeMasterRow()) puts the same claim/release one tap away in the phone kebab, labelled "master" - styled EXACTLY like every other row in that panel (the shared neutral-icon rule, never gold), because it is one session's own control sitting among its session-scoped siblings, not the app-wide state below. And #headerMasterAllBtn ("master all", header-master-all.css) is a single per-browser switch in the app header's top-right corner (rightmost inline control, folding into the same kebab below 768): ON claims size master on every session this browser has attached, and every one it attaches afterward; OFF releases them. It stays lit --oc-yellow-bright while on and a dim --oc-text-dim outline while off in BOTH presentations (the one row in this menu that keeps its own colour when folded, because it names a browser-wide state rather than a per-item action). If a different browser takes master of a session this one was auto-holding, this switch turns itself off rather than fighting back - see web/src/opscenter/api/master-all.svelte.ts. IT HAS A SECOND DOOR TOO, the "master all" item of the drawer footer's account menu (AccountMenu.svelte), with the lit crown #sidebarMasterAllBtn beside the footer's light while it is on (web/src/lib/drawer/bar.ts's DrawerBar.svelte): issue #452 (2026-09-25) takes the WHOLE app header off the terminal page at 1024px and up once the grid is mounted and the drawer is showing - the app's ordinary desktop state - so the header crown alone is unreachable there. common mistakes

  • A second robot, a second kebab, a hand-drawn provider mark. Each exists once; a copy drifts and the same thing is drawn two shapes on two screens.
  • Text standing in for an icon. "Make 'pick' an SVG icon": action icons are SVG.
  • Misaligned tab icons. Mixing 14 and 16 and 20 in one row, or a mark with its own margin, puts the row out of line (#514, #569). Every icon in a tab passes size={14} and centres in a fixed box.
  • Icon-only meaning. A glyph with no label and no aria-label means nothing to a screen reader and little to a new user.
  • A colour choice next to an icon choice, or a second picker. A picked icon wears its parent's colour (Joe, 2026-09-26), and every named thing uses the one IconPicker (#764).
  • An <img src> icon. It is a network request, it cannot take currentColor, and it does not follow the theme.
