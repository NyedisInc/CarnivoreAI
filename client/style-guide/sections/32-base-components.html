base components: card, fold, field, buttons, option list, tag, list, toolbar, state, stat tile, chart frame

The first shared components of the design base (issue #2033, slice 2). Each is a class API that client/js can write plus a thin Svelte component in web/src/lib/base/ that renders exactly that markup. They read only base tokens (web/src/opscenter/tokens.css) and keep a reserved 1px border so the one focus rule (web/src/opscenter/focus.css) lights them. The stat tile and the chart frame are in use: the six stat widgets, the gallery KPI card and the analytics chart cards are drawn by them; the automations list draws its rows, toolbar and empty states with the list, toolbar and state. Keyboard and roles for the fold, the accordion, the option list and the button come from bits-ui, a headless library with no look of its own, pending Alex's ruling on #2033.

card
.oc-card, Card.svelte: ONE bordered level. A title strip in the ledger look (band ground, hairline, the small accent label as the one accent thing), a body with one padding and gap, an optional foot and an optional fold whose button carries aria-expanded. A card never holds another bordered card. An optional lead slot (.oc-card__lead) holds a mark or color swatch before the title (the providers page's account card); any data-* attribute lands on the section, so a test hook is a data attribute, never a class, and data-landed outlines the card a link landed on. title is optional: with no title, meta, lead or actions the card draws NO strip, only the bordered body (pass aria-label); foldable and onopen throw without a title. The strip wraps: the title keeps its width (ellipsis, never crushed by the actions) and the actions drop to a second line when the line runs out; one line when everything fits. onopen makes the title the card's one real button (.oc-card__open); the stat tile's onsub does the same for its sub line (.oc-stat-tile__sub--go). The providers page (ledger) is drawn only with the base set: Card, StatTile, State, Button, Field, Select, Switch, Checkbox, Tag and Fold.
fold and accordion
.oc-fold, Fold.svelte (bits-ui Collapsible) and .oc-accordion, Accordion.svelte (bits-ui Accordion: arrows, Home and End move between headers). No frame: a fold sits in a card body or a panel on the container's left edge. The chevron is the one FoldChevron.svelte.
field
.oc-form-field, Field.svelte: a real label above the base field (data-field, no class), whose boundary is the control line (3:1), help or error below tied by aria-describedby. With no label the bare input is drawn (the bare textarea with multiline), for a row or a popup (pass aria-label, as Select does). block makes a bare input or the search frame fill its container (a filter above a list); iconOnly segmented items wear a narrow pad for header strips. variant="search" (.oc-search, search-field.css) is the framed search box: a leading icon, the input, a clear x drawn whenever there is text (focused or not) with no hover tile, an optional key hint (/ while empty, esc with text) and a trailing slot for a mode button. The frame wears oc-focus-host, so focus brightens the frame's own border. The drawer's search box is this variant; the similar terms under it are base Button chips (role="option") in a horizontal listbox. An optional lead snippet (a scope crumb or an icon) draws inside the same frame after the search icon and before the input (.oc-search__lead); absent, the markup is unchanged. element (bindable, every variant) hands back the rendered input or textarea, so a caller focuses it with no helper; the search variant's older input binding still works.
task wrapper
.oc-task, TaskWrapper.svelte: THE ONE WRAPPER of a task, the same for every task whatever its section, status or kind. It has three states, data-task-state compact (exactly one row: lead, status icon, title and meta), opened (the row and the shared tab strip, always) and detailed (the same parts, every tab panel at full length, nothing clamped). The reply box is the last thing in the tab panel, on the panel's ground and inside its padding, never a part of its own. The state is the host's value; a press on the row asks for the next one (compact, opened, detailed, compact). What only some tasks have, such as a question form, a review block or a scheduled time, goes inside a slot (head, tabs), never in a row component of its own. The room around an expanded task is the shell tokens (--oc-task-pad-x, --oc-task-pad-y, --oc-task-gap). TM Mark II draws every task through it.
small field
data-field with data-size="sm": the base field at the 24px control height and the label type size, for a bar or an add row that sits beside a small button. TM Mark II's search, add and reply boxes are all this one field.
inline field
.oc-inline-field (lib/base/inline-field.css): ONE frame that holds a field and the keys that act on it, in the look of the left sidebar's search. The frame is the 24px small control (--oc-control-h-sm, a rule border, the raised ground, oc-focus-host beside it); the field inside is bare (.oc-inline-field__input, one line high at rest, a textarea grows to three lines); each key after it (.oc-inline-field__key) is squared into the frame behind a 1px hairline, an icon only, muted until pointed at and the accent when something is ready to send; a mode choice is the same key with a native select laid over it (.oc-inline-field__select). TM Mark II's reply box is this.
button
Button.svelte is a plain <button> (or a link) with data-btn and data-size and no class: its whole look is the base layer (foundations: base elements). secondary (the default), confirm, danger, quiet and row, md or sm. Two buttons of one variant and size differ only in their label.
option list
.oc-options, OptionList.svelte: one choice (bits-ui RadioGroup, one tab stop, arrows choose) or several (bits-ui Checkbox), a numbered prompt with a tag, a recommended tag and a reason per row, and a foot for actions. The radio mark is the shared .oc-radio.
tag
.oc-tag, Tag.svelte: a static uppercase word in one of six tones; a pressable filter is still .oc-chip.
list and row
.oc-list, List.svelte and .oc-list__row, ListRow.svelte: one line per row in a fixed order, lead (an LED, an icon or a mark), primary, secondary (muted, gives way first), meta (right, tabular numbers), trailing actions. Three densities from the row tokens: dense 22, default 26, roomy 32. A list has NOTHING on hover (Joe (ccsliinc), 2026-10-26): no tint on a row or a row button; selected, focus and pressed stay. A row NEVER changes height on hover or focus: the state layers move only colors, the 1px border the focus rule lights is reserved at rest, and the trailing actions are ALWAYS SHOWN on every row at rest (Joe (ccsliinc), 2026-10-22: "all records should show all the buttons at once"): nothing reveals them on hover, focus or a pick. aria-disabled="true" on a row is the base disabled look: text dimmed through the dim token, no pointer action, no pointer flag; callers write no local rule. A table row (automations) keeps its own grid of cells and marks its actions cell .oc-list__actions. The wrap prop (data-wrap) lets a row's text wrap in full, no clamp and no ellipsis, for a record that carries a snippet. The below prop (.oc-list__head over .oc-list__below, data-below) keeps the row's one head line (lead, text, meta, actions) and puts the excerpt UNDER it at the full row width, indented to the text start, wrapping freely, never changing on a state (sidebar search variant D). Named oc-list__row because .oc-row is the settings row.
toolbar
.oc-toolbar, Toolbar.svelte: search, filters, a page's own extras, the end pushed right, and an optional row below for removable pills, each slot drawn only when given. Plain, it sits in a page bar (the page kit's PageToolbar draws through it) and scrolls sideways on a phone; .oc-toolbar--band is a standalone strip on the band ground with a hairline under it, and .oc-toolbar--wrap wraps on a phone instead. A control that does not fit goes to the one widget menu, never a menu of the toolbar's own.
state
.oc-state, State.svelte: what a region says when it is empty, loading or failed. Muted words, an optional glyph and hint, an optional row of actions; a warn (something stopped, kind="warn") wears the yellow bar and an error is an alert with the coral bar and the catalog's "try again". A children snippet draws rich words under the title and hint (a list of what stops working), before the actions. Block or .oc-state--inline.
stat tile
.oc-stat-tile, StatTile.svelte: ONE single-metric tile. A small uppercase label (with an optional glyph), one bright figure with an optional unit, an optional change with a tone (.oc-stat-tile__delta--up, --down, --flat), an optional notice, an optional series slot, and a foot (a meter, a quiet line). Size is compact (one unit wide) or regular; mode is line (label and figure only), flat or graph (two units tall, more air). The side inset is --oc-widget-inset at every size, the top inset --oc-space-4 and the bottom --oc-space-3 (a shrunk tile centers its line: --oc-space-3 above and below; a 1 x 1 tile --oc-space-2); .oc-stat-tile--framed draws the card edge for a tile placed with no frame chrome. Nothing changes on hover.
chart frame
.oc-chart-frame, ChartFrame.svelte: the body of a chart card. It draws no title; the host header owns the title (.oc-frame-title), and every part of the body (.oc-chart-frame__headline, __note, __facts, __context, __list, __plot, __empty) takes the same side inset the header takes, --oc-widget-inset, so the body's left edge lines up with the title's at every width. A card without a host header opens with .oc-chart-frame__head, whose right inset (--oc-widget-clear) clears the floating opener.

controls: icon button, switch, checkbox, radio, select, number field, segmented

The controls the base lacked (batch D, issue #2361). Every one is a component in web/src/lib/base/ that wears the one button recipe or the one field (data-btn, data-field), reserves the 1px border the focus rule lights, and reads tokens only.

icon button
IconButton.svelte, icon-button.css (variant="danger" is bare like quiet with the glyph coral at rest: a destructive key, nothing new on hover): the base button at data-size="icon", a square that wears what .oc-ibtn wore. label is required and is both the accessible name and the tooltip (an icon-only control is the one place a tooltip is right). Variants: secondary (the framed square; pressed makes it a toggle), quiet (no frame until pointed at), close (quiet, coral under the pointer), float (the faint floating icon). An optional tooltip is the hover tip when it must differ from the name (a hint, a shortcut); label stays the accessible name. a custom property on the button or an ancestor sets the square; a phone gets the thumb target.
switch
Switch.svelte: a real button with role="switch" and aria-checked, drawn as the app's square check (.oc-check), so Space and Enter work natively and the state is never color alone. bind:checked; a caller that may refuse the change binds with a function binding so a refused write leaves the switch where it was. Optional hint line, note, bare (no frame), glyph (an icon before the label) and role="checkbox" for a member of a set (same look). The opscenter Check.svelte is a thin wrapper over it that keeps its old props and onToggle; new code imports the base Switch.
checkbox, radio, radio group
Checkbox.svelte (tone="danger": the label, box edge and tick in the destructive token, for a warning such as arming a rewind), Radio.svelte, RadioGroup.svelte, pick.css (.oc-pick): the real <input> in its <label>, only the box drawn: a hairline square or circle on the control line, the confirm token filling its middle when on, a dash when mixed (indeterminate, checkbox only). The label is a string or a slot, with an optional hint line. A RadioGroup (role="radiogroup") gives its radios one shared name, so the browser's own keys apply: one tab stop, arrows move and choose. Options as data or as Radio children; orientation vertical or horizontal. The mark sits beside the FIRST line of its label at every width: a label that wraps on a phone does not float the mark mid-block, the thumb height is padding around the first line.
menu item
MenuItem.svelte: one row of an anchored item menu, drawn in the item menu's own look with no CSS of its own (the classes of client/css/session-row-menu.css: .session-row-menu__item with its icon, label, key and reason spans), so a Svelte menu and the legacy item menu cannot drift. label, an icon snippet, keyHint (the key word at the row's end), reason (a line under the label; while disabled it is the tooltip and aria-description instead). disabled is aria-disabled, never the attribute, so the arrow keys still reach it. Nothing on hover beyond the menu's own rule. The caller owns the .session-row-menu panel, focus walk and close; the widgets page's PlaceMenu is the first caller.
select
Select.svelte: a native <select data-field>, the base field (control line, sunken ground, control height, coral when invalid; the drawn caret and the small data-size are in base elements), so the browser keeps the list, the keys and the phone's picker. Options as data ({ value, label, disabled }, or a group) or as a children snippet. With a label it is the labelled column with help and error; without one it is the bare select for a bar, and the caller passes aria-label.
number field
NumberField.svelte, number-field.css (.oc-number): the base field with type="number", min, max and step, and an optional stepper: a base icon button minus and plus either side, at the field's height. ArrowUp and ArrowDown step by step, clamped, with the step's own decimals (0.1 + 0.2 reads 0.3). The browser's spin arrows are dropped. An empty field is null, never 0. The buttons keep out of the tab order (the arrows are the keyboard way) and keep their labels.
segmented
Segmented.svelte, segmented.css (.oc-segmented): a single-choice picker drawn as joined buttons in one hairline frame. A radio group, not tabs: role="radiogroup" of base buttons (data-btn="quiet") with role="radio" and aria-checked, one tab stop (roving tabindex), arrows move and choose, Home and End jump, a disabled option is skipped. The picked option is the base picked state. iconOnly draws only each option's icon (the label stays its accessible name and tooltip), for a header too narrow for words. An option may carry its own title (its hover tip), which wins over the icon-only label tip. Tabs that switch a panel stay Tabs.svelte (page tabs) and the terminal strip; never build a second tab component from this.

every shipped theme, and the theme contract

Each tile wears one theme alone. The line under it is that theme's standing against the theme contract (client/js/themes/theme-contract.json): a theme may set its colors, one font family and two clamped corners (--radius-control 0 to 4px, --radius-panel 0 to 8px); anything else it sets is reported here and logged by the server when the theme loads, never acted on yet.
