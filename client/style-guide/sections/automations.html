automations page

The menu page for saved schedules: three tabs. automations is the simple overview (tiles and cards), sessions is a simple review feed of runs with a quick-view drawer, and advanced keeps every older feature, unchanged: a sortable table of automations beside a detail pane (output, runs, overview, log, and the editor), the run feed with its reader, the counter strip, the log dock and the commands popover. It wears the manager frame (ManagerFrame: title strip, the one primary "new automation", the page's one sentence) and supplies its own body. It is a client of the automation routes only, and it follows the automations and automation_runs push topics, polling only while one is not live. The sections below that say "tab" for the table and the run feed describe the sub-tabs of advanced.

the three tabs: overview, review feed and drawer

tabs
Three top tabs in the shared tab row (.ap-toptabs, .ap-tabrow), remembered per device. The sessions tab wears the unread badge (.oc-ptab__badge). AdvancedTab holds the older page inside .ap-adv: a head with the page sentence, the pause switch and the commands popover (.ap-adv-head, .ap-adv-sum) and the two sub-tabs table and run feed (.ap-subtabs). Deep links #automations/advanced, #automations/run/<id> and #automations/session/<uuid> land there.
overview
review feed
ReviewTab and ReviewRow: a time-ordered feed of runs (.t-feed, .t-feedbar, .t-day) with the filter segment to review or all (.t-filt) and mark all reviewed. A row (.f-row) is the time (.f-time-in), a dot on a spine (.f-dot), the automation (.f-who) and a status word (a base Tag), the run title (.f-title, --oc-fs-run-title), a one-line summary (.f-sum) and the outlined looks good action (.f-act); reviewed rows fold out. Title and summary are written by code on the server, never by a model; a run stored before they existed shows the older feed face line. Keys j k enter r (.f-keys).
drawer
ItemDrawer (.ap-dr, a non-modal side panel, role="complementary") docks at 420 px from 1100 px of page, covers the page below that and is a full sheet with a back button (a base Button) at phone width. Title bar .ap-dr-bar, scroll body .ap-dr-scroll, sections base Cards with a small uppercase label .ap-dr-lab. AutomationDrawer: name (.ap-dr-name), switch, run now, the next three runs (a base List), the last run (LastRun), edit and open in advanced (base Buttons). RunDrawer: the run, its title and summary (.ap-dr-title, .ap-dr-sum), attachments, a since sentence against the previous run and the full report in advanced. Focus moves in on open and back to the opener on Escape; Tab stays inside.
schedule field
The editor's when field (WhenField, .w-when, a base Segmented) has three modes: words (type a sentence, read back in words with the next fires, WhenWords), pick (repeat, weekday chips .w-days, a calendar .w-cal, hour, minute, am or pm, WhenPick) and cron (the field as before; a fire under 15 minutes apart is refused). Switching modes reads the schedule back. The day-of-week field also reads dow#n (2#3 is the third Tuesday). Each field carries a hint (FieldHint, .w-hint) and an example, and IdeasList (.w-ideas, .w-idea) fills the form from a one-line idea. Create stays blocked until the schedule is confirmed.

the list and the editor

pattern
The automations tab is AutoList (.ap-listcol): the toolbar, ONE sortable table (.ap-list, .ap-lhead, .ap-row) whose columns are record fields, the newest-run line and the key hints. The table is a container (container-type: inline-size), so its columns follow its own width, not the window: from 680 px the last-12 strip and the ok rate, from 900 px the on switch, from 1100 px the next run and the median took (.ap-c-next, .ap-c-strip, .ap-c-rate, .ap-c-med, .ap-c-on). The table is the base list (.oc-list) and each row a base row (.oc-list__row): a selected row is the selected layer with a 2 px orange left edge, and run now with the kebab (.oc-list__actions) shows on hover, focus or selection, always on a phone. On a phone there is no header row and a row is two lines.
toolbar
AutoToolbar (.ap-lt, the base toolbar's band strip, .oc-toolbar--band): hairline groups (base Field/Select groups) each with a small uppercase label (the field label): find (the base field, data-field), add filter and sort (a base Select, with the direction button a base IconButton), then the density radios (a base Segmented), clear (only while something narrows the list) and the live count (.ap-lt__count), all on one row from about 900 px of list width; narrower, the density and count drop under the groups. Removable filter pills (.ap-pill) sit in a row below. Rows show when the pressed counter AND every pill AND the search all match.
row
AutoRow: the health light, the name with its needs-attention tag (the base tag, .oc-tag, the first matching of waiting on you, last run failed, skipped lately, newest output empty, switched off) and the schedule in words (.ap-l2), the next run, the last run (.ap-lr), the strip, the rate, the median, the on switch (the shared .oc-check, its word hidden in the cell) and the outlined run now (the base confirm button, data-btn="confirm" at the small size) with the kebab (a base IconButton). RowMenu (the app's one menu, CascadeMenu) offers edit, duplicate and delete; delete asks in a strip (.ap-confirm) with the restart picker's danger button.
marks and strip
Mark draws a run status as a shape (.ap-mk-run, .ap-mk-light): succeeded a filled square, failed a struck square, skipped a hollow square with a gap, waiting on you a diamond that breathes, running a dashed ring that turns, claimed a hollow square. RunStrip (.ap-strip-box, .ap-strip-in, .ap-sm) is the last twelve runs, oldest left; the run shown in the pane has an orange outline, a landed run slides the strip in over 200 ms unless motion is reduced.
scheduled tree
never ran
An automation with no run shows a base State in the pane's output tab: the page's empty-state look (no frame, muted words), a hollow square mark, the words never ran in the small tracked label, the next run, and the one run now action, centered in the body.
newest-run line
NewestRunLine (.ap-pv) reads the selected automation's newest run (or the run the pane is stepped to) as one line; KeyHints (.ap-keys) names the table's keys and hides on a phone.
editor
target picker
TargetPicker offers a target kind only when the server lists a runner for it and a form exists in target-forms.ts. A later target adds one line there and its own form file. TargetRecipe draws the recipe's whole-number params from the schema the server sends. TargetBlueprint lists the saved Blueprints (a select) and one square check per member (Check); all ticked saves every member, including ones added later. TargetCard picks a project board and takes the card's title, summary, text and how to validate (each with the board's length cap shown), plus one Check switch to start the card right away.
cron agent form
page shell
AutomationsScreen draws its own title row (.pl-titlebar, the one accent label, then the live sentence .ap-sum and the actions .ap-acts): scheduler log and commands (the base button at the base size every title bar wears), the pause scheduler switch (.oc-check, the square check look, yellow while on) and the outlined new automation (data-btn="confirm"). A paused scheduler also shows .ap-strip. The root is .ap-page (page.css).
tabs
Under the title the page wears the shared page tabs (Tabs, .oc-ptabs, flattened here by .ap-tabs to the mockup's strip): automations and sessions. There is no Task Manager tab. The chosen tab is remembered per device (carnivore.tabs.automations, try/catch); a remembered huddle reads as automations.
counter strip
CounterStrip (.ap-ctb): eight toggle buttons (.ap-ct), a micro label (.ap-ct__l) and a figure (.ap-ct__n). The numbers come from the server, failed counters are coral and waiting on you yellow only above zero, a pressed counter wears the orange border and tint and is shared by both tabs, and a changed count flashes once for 1300 ms (off under reduced motion).
log dock
LogDock (.ap-logdock): the scheduler log of every automation under the list, at most 38% of the page, its header (.ap-logdock__h) sticking, a close button, and the rotation settings after the lines.
commands popover
CommandsPopover (.ap-cmd-wrap, .ap-cmd-pop): the allow-list under the commands button, editable, closed by a click outside or Escape; fixed with a 16 px gutter on a phone.
schedule this
The drawer's session row menu and project menu carry "schedule this". It opens this page at the fragment #automations/new/session/<session_uuid> or #automations/new/project/<project_id> (schedule-prefill.ts), which puts the new-automation editor up with the target (and project) filled in and then takes itself off the address. Save is still the one authenticated create call.

contract fields, more targets, change log and scheduler log

contract fields
ContractFields sits in the editor under the schedule (.auto-form__group): what it is for (a textarea), the project (a select that leaves archived projects out), what to do about a missed run (run once, the default for a new automation, or skip), retries (0 to 3) with the wait, and the longest a run may take. Times are typed in minutes and saved as seconds. The search reads an automation's description and its project too, and the project is shown as an a base Tag.
more targets
scheduler log
SchedulerLog (.auto-log, a base ListRow): the scheduler's own lines, newest first, read on open and on the automation_log push topic. Above them the rotation settings: by size (with a size in MB) or daily, and how many old files to keep, saved through PUT /automation-log/settings.

the detail pane

pattern
DetailPane is the page's right column (.ap-pn), sized by the PAGE, never the window: the page is a container (ap-page), and from 900 px of page the pane docks at 36% of it (340 to 760 px) while the list, the title bar and the strips stop at its left edge; under 900 px it covers the whole page. The title bar is its own container (ap-title) and drops the sentence under 1000 px of bar. It slides in over var(--oc-motion) and the body fades 150 ms when the tab or the run changes (.ap-pn-fade), both off under reduced motion. A title row (.ap-pn-bar), the head or the editor, four tabs (.ap-pn-tabs) and the body. [ steps to the older run, ] to the newer one, Escape closes.
head and editor
output
OutputTab: the run stepper (.ap-pn-step, a base Button with the neighbour's mark, .ap-tri), then RunSheet with its action row.
runs
overview and log
OverviewTab: a label and value grid (.ap-pn-dl), the next five runs (.ap-pn-fires), what ran in a base fold (.oc-fold; its settings are .ap-pn-chip), then the change log (a base List, rows a base ListRow). LogTab: the scheduler lines of the run or of every run (a base List, a base Segmented segmented control), oldest first.

the generic report renderer

pattern
RunSheet draws one run's stored report by shape, for every automation, with no key known by name beyond the reserved ones (summary, metrics, items, exit_code, stdout_tail, stderr_tail, error, fix_prompt, conversation_uuid). It has two compositions: pane (header, error, body, a changes chip, raw json, then the action row) and reader (error, body, the "since #n" changes section, raw json). Report text is always drawn as text, never as HTML. Every part wears the .r-sheet rules of report.css.
header
RunHeader: the status line (a run mark, the status word and the reason) with the run number, then base Tag chips for the trigger, the timing, the cost, the output size ("of 1 MB cap" at 524288 bytes), the exit code, the sessions and the computer.
body
ReportBody draws the summary (.r-summary), the exit-code tile, the metric tiles (Tiles, .r-tile), stderr above stdout on a failed run and below it on a good one (.r-sec), the items list (.r-items), the small fields (.r-kv) and one section per remaining key. A report with nothing in it says what happened (.r-empty), never a blank.
rows
text
LongText clips a long string to its first 12 and last 3 lines (.r-clipbar); Markdown draws headings, lists, fences and pipe tables (.r-md, .r-mh, .r-code); RawJson is the copyable raw JSON, a closed foldable base Card.
changes
DiffSection: the one-line sentence (.r-chg-s), the header deltas, then new, cleared, numbers changed, values changed and text changed with a +, - or ~ gutter (.r-cl). The pane opens it from a foldable base Card titled changes.

the sessions tab: run feed and reader

The second tab is a feed of every automation run (FeedTab) beside a reader, and from 1700 px a third column. Copied rule for rule from the accepted mockup; every colour is an --oc-* token and the sheet is web/src/lib/automations/feed/feed.css.

layout
.ap-sx is the grid (feed, reader, and at 1700 px and wider .ap-cx, this automation's last twelve runs, drawn by ContextColumn). .ap-feed holds the filter block FeedTop (.ap-fd-top, .ap-fd-row1, .ap-fd-row2, the search field a base search Field, a base Select for the five selects, lit with data-on while one filters), the counts line (.ap-fd-meta, .ap-fd-meta-b) and the list FeedList (.ap-fd-list, an ARIA listbox the keyboard walks) above the key hints (.ap-keys).
rows
A day head is sticky (.ap-fd-day, .ap-fd-dc). One run is a 32 px grid row FeedRow (.ap-fd-r): time .ap-fd-t, mark .ap-fd-mk, name .ap-fd-nm .ap-fd-n1 with a trigger word .ap-fd-tg, where it files .ap-fd-wh, the face .ap-fd-f .ap-fd-ft (changed words .ap-fd-chg, a fold caret .ap-fd-car), took .ap-fd-tk and size .ap-fd-sz. Unread is a 2 px orange bar, selected a 1 px hairline, changed is brighter, a repeat is dimmer. Identical repeats fold into one row whose members open under it (.ap-fd-ms, .ap-fd-m). A new row slides in over 180 ms and a fold's face rolls over 220 ms, neither under reduced motion. Messages and paging: .ap-fd-msg, .ap-fd-more, .ap-fd-end.
reader
ReaderSheet (.ap-dc, .ap-dc-scroll, .ap-dc-wrap, a back Button) is a column on a desktop and a full-screen sheet on a phone that slides in and walks runs with a swipe. Reader draws the head (.ap-rd-head, .ap-rd-kick, a quiet Button with the automation name, .ap-rd-num, .ap-rd-rel, .ap-rd-stl, .ap-rd-stw, .ap-rd-reason, .ap-rd-since), the facts (.ap-rd-def), the action strip (.ap-rd-strip, .ap-rd-nav), then the body (.ap-rd-in) with the generic run sheet and the record section; attachments are links (.ap-rd-file). With no run it shows the templates (.ap-rd-none, a base Tag).
